WHY THIS LAYOUT
---------------
The first attempt at these mutations used %TEMP%\pf-v2-mut\pkg\.  There the firewall
check C4.1 necessarily FAILs (no rule names a %TEMP% path), so the verdict took the
"Fails>0 -> ACTION NEEDED" branch every time.  Every caveat-layer mutation was
therefore invisible: the exit code was pinned at 2 and the caveat block never ran.
That is a property of the test layout, not of the script - and it would have let a
bogus "mutation caught" claim through.  Running at a firewalled-covered path removes
the noise: the clean baseline is "READY WITH CAVEATS", 0 FAIL, exit 0.
