## 1. 必须整改（P1）

### R1：重做卸载状态机（对应审计 P1-1、P0-2）

- 允许 `CivTraceShutdown` 返回 0 或幂等返回 1 后进入同一卸载流程。
- 不以固定的“两次 FreeLibrary”猜测引用计数。明确本工具每次成功 LoadLibrary 对应的引用责任，逐次读取远程线程结束状态与退出码；任何无法确认的步骤停止后续危险操作并报告当前状态。
- 处理“Shutdown 已完成但首次 FreeLibrary 失败/超时”后重试的恢复路径。
- 保持 PE 身份拒绝路径；修复 `GetExitCodeThread` 调用失败被默认 code=0 的问题；严格验证远程模块枚举结果完整。

### R2：建立可证明的 Hook 停止/排空顺序（对应审计 P1-2、P0-5）

- 对 Hook 安装与 Shutdown 建立同步状态机，确保关闭开始后 InitWorker 不会继续装钩。
- 成功禁用全部 Hook 后才允许释放日志资源；禁用失败时保留 DLL、队列和日志资源，且不返回可以 FreeLibrary 的成功码。
- 为“在途 Hook 已退出”提供显式同步证明或采用 MinHook 已保证的等价机制并注明依据；不把刷盘线程 join 当成 Hook 排空证明。
- DllMain detach 兜底不得在无法证明安全时关闭仍可能被 Hook 访问的资源；明确定义进程退出与显式卸载的不同处理。

### R3：刷盘线程创建失败时 fail closed（对应审计 P1-3）

- 若启动 FlushLoop 失败，不启用追踪 Hooks；写入可观测错误（至少 OutputDebugString/注入器状态可查询），避免只把错误放进无法及时落盘的队列。
- 增加可确定触发线程创建失败的测试 seam 或独立单元路径，验证强杀时不会宣称日志保障成立。

### R4：进程选择必须完整且可审计（对应审计 P1-4）

- `FindPids` 动态收集所有匹配 PID，或在上限到达时明确失败并报告截断，禁止静默采用数组内第一个目标。
- 路径查询失败明确显示 PID 与错误码；无 `-p` 且多实例时建议要求显式消歧，至少保证操作员能核实实际选中完整路径。

### R5：架构和权限探测失败时拒绝操作（对应审计 P1-5、P2-2）

- 用 `IsWow64Process2`（含兼容回退）或对现有 `IsWow64Process` 失败采取 fail-closed。
- 检查并报告调试特权启用结果、`ERROR_NOT_ALL_ASSIGNED`、目标架构与权限失败原因。
- 注入和卸载均必须经过相同的架构验证。

## 2. 应整改（P2）

### R6：模块枚举缓冲动态扩容并区分不可判定（P2-1）

PSAPI 返回的所需字节数超过缓冲时重试；重复变化或失败时返回“不可判定”，不可伪装为模块不存在。覆盖模块数超过初始容量的测试。

### R7：降低并准确描述观察开销（P2-3）

- README 将保证表述限定为“Hook 不同步写磁盘；日志仍有锁、分配与系统调用开销”。
- 确保日志失败/丢行信号可被发现；分析脚本遇到 seq 缺口或 drops 时应将受影响的时延/生命周期结论标为不完整。
- M0-A H6 结论必须以抓包时间戳为主，并用 QPC/日志仅辅助关联，保留原生对照。

## 3. 验收证据（修改完成后再执行）

1. 干净 MSVC 构建日志、工具版本/架构、DLL 与 EXE SHA256。
2. 自动化或可复现脚本覆盖：Shutdown=0、Shutdown=1 后卸载、FreeLibrary 失败/超时后重试、错误 DLL、远程 PE 不匹配、32 位目标及架构查询失败。
3. Hook 安装/Shutdown 并发、禁用失败、刷盘线程失败、强杀路径；证明失败时不错误卸载、不丢失资源状态。
4. 超过初始 PID/模块缓冲容量时不静默截断；目标路径读取失败有显式诊断。
5. 错误码测试需让目标线程在 Hook 前后读取 `WSAGetLastError` / `GetLastError` 并比较精确值；Overlapped/IOCP 需覆盖成功、Pending、失败和失败完成包。
6. 证据必须绑定本次构建二进制哈希，记录命令、环境和原始输出。标注源码确认、测试确认、推断、未验证，不以代码审查替代运行证据。
7. 工具级整改通过后，另行执行 v1.1 README 的真实 Civ6 E1–E5；若设备或 EOS 构建不可用，如实标注未验证，不以合成负载代替。
