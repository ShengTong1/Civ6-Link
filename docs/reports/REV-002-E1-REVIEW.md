## 1. 独立复核到的证据

- `M0A/captures/E1-20261111_1510/F1-broadcast-lines.txt` 展示连续 sendto 记录，目标为 255.255.255.255:62900 起、载荷 `8d e8 fc 70`、长度 4。
- `F1-discovery-socket-0x868.txt` 显示该发现 socket 的 socket → setsockopt → sendto 序列；报告将 socket 生命周期、select 与 closesocket 归因到日志分析。
- `native-probe2.log` 与 `native-after-stop.log` 显示监听器绑定 62900–62999 并收到包；文件样本覆盖端口全谱，报告统计注入期 100 包、停用后 300 包。
- `shutdown-sequence.txt` 记录首次 shutdown 因 `in-flight hooks=1` 超时返回 2、12 秒后重试成功。这是 civtrace 在真实 Civ6 进程中触发 B1 的直接证据。
- E0 基线目录记录 Steam Build ID 26407122；README v1.3 已补充运行目录与抓包降级流程。

本次仅审阅工作区实际交付的切片与日志，没有原始完整 trace（报告称其仅留在 `%LOCALAPPDATA%`），也没有 pcapng；未重新运行游戏、重新计算所有证据哈希或从完整原始 trace 重算统计。E1 报告明确披露了这些边界。

## 2. 结果裁定

### F1：采信为本机 Steam 构建下的 C 级单机发现证据

三轮各发 100 个 IPv4 limited-broadcast 包、目标端口 62900–62999、载荷 4 B，可由 trace 摘录和用户态监听记录相互支持。`sendto` 与随后 `select` 等待约 2 秒的观测，支持把该版本/该发现流程描述为“每次刷新触发一次 100 包突发，随后在原 socket 上 select 等待”；现有证据没有证实回复路径，因此 F2 回复行为仍留待 E2。

“无需周期重发”只能作为该三次用户触发样本的观察结果，不能外推为任意 UI 状态/版本都绝不重发。Agent 重试策略属于产品设计输入，不由 E1 单独定案。

### H5：采信为限定环境下“本机可收本机广播”成立

监听器成功绑定 100 个端口并收到完整端口范围，支持 H5 在 Windows 11 build 26100、当前网卡/路由和监听器 ReuseAddress 设置下为“是”。该结果不能单独证明无 Hook 的完整 Discovery Adapter 可行，也没有验证外来房间响应可送入游戏 socket。Radmin VPN 地址作为源地址说明该机器的接口选择受路由/接口配置影响；不能推导所有机器都按“最宽前缀”选出口。

### F5/F2 修订：部分采信

日志支持本次发现轮次用 `socket/setsockopt/sendto/select/closesocket`，且目标 socket 未见 bind 或 recvfrom/WSARecvFrom 调用。应将结论限定为该 Civ6 DX12 Steam Build 26407122 的本次 LAN 刷新路径。F2“回复包到达原 socket”没有被本次单机实验验证；只有等待方式观察，不可据此改写回复行为为已证事实。

### H3：保持未裁决

WSAPoll、WSAGetOverlappedResult、select 的进程级调用统计未能按 socket/端口证明这些调用对应 62056 游戏数据 socket；报告也说明未开局、62056 无活动。因此它们只能说明该游戏进程/相关模块在当前会话中调用了多种 API，不能据此说游戏数据面三种 I/O 模型并存，也不能推翻或确认 F4 数据面模型。须在 E3 将调用归属到具体 socket、端口和进程模块后再裁决。

## 3. 应在规范/报告中保持的限定

1. **SO_BROADCAST A-6 未解决**：`setsockopt` 日志显示 val=0 与实际 sendto 成功存在矛盾。`Hook_setsockopt()` 在 `trace_dll.cpp` 约 811 行直接解引用 `optval` 前仅检查非空和 `optlen >= sizeof(int)`，未校验指针可读性；但这只能说明追踪器的读取方式值得核查，不能证明游戏的真实选项值是 0。不得据此指导 Agent 不设置 SO_BROADCAST。
2. **H5 不是 Design III 通过结论**：它只验证同机出向广播可被本机绑定 socket 收到，不验证端口冲突边界、发现回复注入、路由/防火墙多环境行为或完整适配器链路。
3. **进程可见性限制的根因尚未由交付证据独立确认**：报告记录“项目目录运行枚举 29、中立目录 361+”，足以作为本机操作规避说明；排除项和环境诊断缺少可复核原始输出，因此“目录级环境限制、非代码缺陷”应标为执行者归因/推断，不作为已证根因。
4. **A-4 日志量级确实是工具可用性风险**：66 MB / 14 分钟以及大量 Steam/EOS 模块事件会污染总体统计并增加证据筛选成本。当前工具验收仅针对安全审计运行模式，不代表已验收长时采集可用性。未经批准不得在本轮自行改采样语义；后续如要减少日志，需保持关键网络事件完整，并对降采样结果重新做取证有效性评估。
5. **标准 E1 的对照仍缺失**：本轮原生组是同 PID 停用 Hook 后采集，且没有 pcapng。README 已明确这属于降级执行。其对照只能表述为“停用后发包面与注入期相同”，不能替代标准流程的重启后不注入对照，也不能支持“civtrace 无副作用”强结论。

## 4. 阶段决定

本次 E1 对 F1/H5 提供了有用的单机 C 级证据，并真实验证 B1 超时恢复；它不是完整标准 E1，更不是 Gate A。建议将 E1 状态记为“降级执行，部分结果可采信；待补干净重启原生对照与完整抓包”。

Gate A 自检仍缺 F2 回复行为、F3/F4/F6、H3/H4/H6(response)/H7/H11、数据面 R 指标、pcapng 和 Civtrace 无未解释异常。E2/E3/E4/E5 尚未完成前，**Gate A 不批准，M0-B 不启动**。
