# P2 H6 响应窗口复核（2026-11-13）

- **复核对象**：`P2-H6-RESPONSE-WINDOW-20261113.md` 及其原始证据
- **复核性质**：单机、有界合成响应实验的证据复核；不是 Gate A 验收
- **授权依据**：`REV-014-REVIEW.md` §4
- **结论**：主实验的限定时序结果可采信；“20–50 ms RTT 已验证”不成立；后续观察轮超出原授权范围，单独列为范围偏差

## 1. 复核材料与方法

复核了主实验目录 `M0A/captures/P2-h6-20261113-144200/` 中的 `summary.txt`、`requests.log`、`post-response-traffic.log`、`precheck.txt`、`fixture-hashes.txt` 和 `civtrace-snapshot.log`；另检查了 responder 与分析器源码、观察轮目录 `M0A/captures/P2-h6-observe-20261113-144656/` 及列表截图。

复核方使用仓库内 `scripts/analyze-h6-window.ps1` 对 94,033,366 字节的 trace 快照重新计算。摘要、请求日志、后续流量日志、预检、fixture 清单、responder 和分析器的 SHA256 均与提交报告列出的值相符；主实验 summary 的 SHA256 为 `4AEEAA0FB57EA8E105BA50EF4FE3F5C7E0FC6356CCEB437F50328E6080BE1BA1`，responder v2.3 为 `FDE71D31EAD82B3667793A7DAF4FCE98F75ED8CE4EF81E68F37B186F0EFCF244`。

## 2. 主实验可采信结果

| 轮次 | 广播包/端口 | `T_response` | 收到页数 | 最后响应至 close | `T_window` |
|---|---:|---:|---:|---:|---:|
| 1 | 100 / 100 | 74.182 ms | 22 × 1104 B | 1619.696 ms | 2016.987 ms |
| 2 | 100 / 100 | 13.997 ms | 22 × 1104 B | 1691.612 ms | 2024.513 ms |
| 3 | 100 / 100 | 15.170 ms | 22 × 1104 B | 1684.723 ms | 2018.729 ms |

分析器复算得到 `sendto=300`、`recvfrom=66`、3 个完整发现轮次；每轮 22 页均为 1104 B。Responder summary 记载 3 次响应（预算 3）、`receive errors=0`、`select errors=0`，请求日志的 3 个请求均为本机来源。数据与执行报告的主实验表格一致。

因此，以下**限定事实**予以采信：在本机、本构建、主菜单、观察工具注入及本机合成 responder 即时回包的条件下，三轮发现 socket 都没有因收到 22 页回复而立即关闭；每轮在最后一个已观测回复后继续存活约 1.62–1.69 秒，总发现窗口约 2.02 秒。

## 3. 不能外推的结论

1. **没有实际注入 20–50 ms 延迟或测量 Relay RTT。** 主实验只证明直接本机合成回复之后仍有较长存活时间。因而“+20–50 ms RTT 完全容纳”“中继余量约 2000 ms”不是实验直接结论。可将 50 ms 远小于本次观察到的响应后存活时间作为待跨机/延迟实验验证的推断，不应写作 H6 已通过。
2. 报告中的 `T_response` 是从本地 trace 计算的“首个发现广播到首个接收响应”的时间，不是网络 RTT；首轮 74.182 ms 还包含 UI 与本机调度等影响。
3. 这不是双机响应、真实房主、跨网卡转发或联机加入实验，不替代 E2-B、E3，也不启动 M0-B。
4. trace QPC 只提供本进程单调时钟上的本地顺序和时长。Responder 的墙钟日志可作事件关联，但不能将两个进程的墙钟差直接当作精确 RTT。

## 4. 授权边界偏差与证据等级

- 主实验目录记录 3 次响应，未超过 REV-014 §4 的单轮 3 次响应上限。两次较早的 responder 运行分别记录 0 次响应；作为无匹配请求的尝试，不纳入主实验样本。
- `P2-h6-observe-20261113-144656/summary.txt` 记录主实验之后另开 responder 会话并发送 2 次响应。它是额外运行，不能并入原先“批准一次、最多 3 次响应”的 P2 授权；本复核不追溯批准这 2 次发送。该目录只作为偏差记录和辅助观察，不纳入 §2 的 H6 数值。
- 观察轮截图可以看到列表有一行，但游戏名称列被画面裁切，截图本身无法读出 `CivLink-Test-Room-2222`。精确房间名仍依赖负责人当场口述及请求/发送日志关联，按 D 级观察记录。它不影响主实验 socket 时序结论；更完整的本机合成公告列表证据见 `E2B-SYNTHETIC-CLIENT-REVIEW.md` 所引的既有截图。
- 主实验按授权未要求 pcapng/UAC；现有本机日志足以复核上述应用层时序，不据此作二层路径结论。

## 5. 裁定与后续

- **P2 主实验：限定结果通过复核，可作为本机合成响应时序证据入档。** 正式措辞应是：“三轮本机合成即时响应中，收到 22 页响应后发现 socket 仍保持打开约 1.62–1.69 秒；本地 `T_window` 为 2016.987–2024.513 ms。”
- **H6 / E2-B：未完成。** 不把 P2 作为真实中继 RTT 验证，不替代双机、多轮和真实响应条件下的 E2-B。
- **范围偏差：观察轮额外 2 次响应未包含在原授权内。** 保留原日志并如实披露；不以该轮支持 P2 主实验通过，也不继续重复类似合成响应实验，除非另有明确授权。
- **S1 Phase 0：可按 `REV-014-REVIEW.md` §1.1、§3 立即继续。** 仅限隔离的非发布原型、只读接口诊断、现有 fixture 离线解析和 mock UI；不改网卡、不发送真实发现流量、不接管 Civ6 socket、不注入产品 DLL。
- Gate A 仍未批准，M0-B 仍冻结；E2-A 仍部分完成，E2-B/E3 仍待真实双机资源与对应实验。
