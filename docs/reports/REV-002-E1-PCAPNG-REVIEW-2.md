## 2. 新发现的非阻断事项

### N-1：时间戳摘要精度不足，且报告中的最大差值过小

**级别：P2；不阻止 E2 抓包，但修正前不得引用重复帧副本的精确微秒差。**

脚本第 21 行把 pcapng 时间戳转换成 `[double]` 微秒，第 157 行将其直接导出 CSV；CSV 的 `FirstTs` 使用科学计数法，不能保持每条捕获时间戳的原始整数 tick。脚本也没有将每个副本时间戳逐条导出。

本复核直接读取 pcapng 原始 EPB 时间戳。IDB 未提供 `if_tsresol`，按 pcapng 默认分辨率为微秒。300 个身份的副本时间跨度分布为：**0 tick × 78、1 tick × 216、2 tick × 3、5 tick × 2、14 tick × 1**。因此 E1 分析 §2 第 2 条和 §3.4 所称全部副本相差 `0.1–2 μs` / 最大 `≤1 μs` 不准确；8 条记录的 Hyper-V 身份跨度为 **14 μs**。

建议保留 `timestamp_ticks` 为 64 位整数，并逐身份导出 `first_tick`、`last_tick`、`span_ticks`；摘要按 tick 转换为 µs。不要用浮点格式化后的科学计数法证明微秒级差值。

### N-2：帧一致判据在解析器中没有实现

分析文档 `M0A/captures/E1-pcapng-ANALYSIS.md` 第 42–45 行称解析器按整帧字节核对副本；当前脚本只收集已解析字段并按 tuple 分组，没有保存帧字节或计算帧哈希。对当前原始 pcapng，本复核另外逐帧计算哈希，确实得到每个身份内帧字节一致；但脚本本身不能复现这项判据。

建议在解析器中保存捕获帧 SHA256（不含 EPB 时间戳/块元数据），并对每个身份断言帧哈希唯一值为 1。此项是归档可复现性修正，不阻止开始 E2。

### N-3：把 63107 称为“未解释的 +1 缺口”缺乏依据

E1 报告 §3.2:178、分析文档 §3.3:127–128 将 Radmin 段从 63108 开始、Hyper-V 源端口 62900 的 ID=59639，描述成“未解释的 +1 缺口”，并反事实地说若在 Radmin 空间应为 63107。抓包只证明该身份呈现为 Hyper-V 源地址/MAC；没有证据证明它同时在 Radmin ID 序列中分配过 63107，也没有取证证明 Windows 的 ID 分配按网卡/源地址划分。

应改成“第一轮 62900 的单个身份显示为 Hyper-V 源，其与其余 99 个 Radmin 源身份的接口/源地址差异原因未裁决”；删除“+1 缺失 ID”及“不同接口各自分配 ID 空间”为已证事实的表述。这个观察可作为 E2 的待观察项。

## 3. E2 入口判定

**可以开始使用第二台真实 Civ6 电脑执行 M0-A 的 E2-A/E2-B；无需等待 N-1 至 N-3 完成。**这些问题涉及 E1 归档精度/解释，不影响双机实验本身。执行时：

1. PC-A、PC-B 分别完成 E0，记录 Build ID、游戏/DLC、Windows、网卡接口索引/IP/MAC、活动路由及防火墙差异；两台必须在同一可达 LAN。
2. E2-A 按手册执行：A 建房并注入，B 原生不注入；两端在点击刷新前开始完整抓包。被动保存响应包、来源地址和原始 1104B JSON，不改包。
3. 对“轮1 端口 62900 源地址/MAC 不同”的观察，两端均保留完整 pcapng/接口清单/路由快照；只报告实测，不先归因路由选择。
4. E2-A 结束后两台完全退出 Civ6，再各自重启后执行 E2-B。`-u` 依 v0.4.4 仅停用并保留 DLL 映射；切换注入状态必须新进程。
5. E2 结果可补充 F2/H4/H6/H9/H10，但**不能代替 E3 的 H3/62056 归属，也不能代替 E4 三机 H7/H11**。

双机阶段只允许继续 M0-A 证据收集；**不批准 Gate A，不启动 M0-B**。按 v2.1 §11.1，E4/H7/H11 仍需三个真实 Civ6 端；如果项目最多只有两台，这些项目在现行验收范围内仍未满足。
