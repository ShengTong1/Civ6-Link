## 2. 关键问题：IPv4 Identification 按错误字节序解码

**级别：P1，阻断将当前去重论证作为独立验证结论。**

IPv4 头中的 Identification 是 16 位网络字节序字段。独立读取原始帧后，第一轮 Radmin 源地址数据报中，目的端口 62901 的 IP ID 为 **63108（`0xf6e4`）**，62902 为 **63109（`0xf6e5`）**，差值为 **+1**。原分析文档 §2.3:52–66 报告的 `59638, 59894, ...`（差值 +256）与原始头字段不符；这一 +256 模式符合将相邻的网络字节误按小端解释时产生的数值变化。

同样，分析文档 §2.3:47–48 的代表值 `46582`、`63464` 与独立解析所得线上的字段值不一致。例如端口 62950 第一轮的字段值为 **63157**（4 条记录均相同），第一轮 Hyper-V 源的 62900 数据报字段值为 **59639**（8 条记录均相同）。

因此：

- **不采信**“IP ID +256 连续序列证明单次发送循环”的推论；必须用网络字节序重新生成逐包明细及差值统计。
- “同一数据报的多条捕获记录具有相同 IP ID”与本次原始帧复核相符，但**仅凭 IP ID 相同不应写成真实重发必然递增的普遍定律**。建议以完整帧字节（排除时间戳/捕获元数据）哈希、UDP tuple、载荷、IP ID 及 pktmon 捕获点标记共同去重，并披露匹配规则。
- 在完成重新解析前，可以陈述“本文件含 1,204 条匹配记录；按当前网络层键归并为 300 个身份”，不可把错误的 +256 判据称为独立证明。

**源码/测试/推断分类：**这是对原始测试证据的独立解析结果；不是源码结论。关于 pktmon 多捕获点导致记录重复，属于目前证据支持的解释，但捕获点元数据尚未在本复核中检查，故为**高可信推断，未完全验证**。

## 3. 网卡与路由结论超出证据

**级别：P1，需修正文档结论；不阻断单机 E1 的有限观察结果。**

E1 报告 §3.2:138–139 与分析文档 §2.2:35–37 表述不一致：分析文档称第一轮 100 包均来自 `172.27.112.1`；报告称第一轮中只有 8 条 Hyper-V 记录，其余来自 Radmin。对原始 pcapng 的独立解析显示：

- 第一轮源端口 50731 中，**396 条捕获记录**源地址为 `26.74.126.98`；**8 条**源地址为 `172.27.112.1`。按字段归并后，99 个目的端口的数据报为 Radmin 源，目的端口 62900 的一个数据报为 Hyper-V 源。
- 第二轮源端口 57605、第三轮源端口 57606 的捕获记录均来自 `26.74.126.98`。
- 报告把第一轮写作“走 172.27.112.1 路径”会造成整轮归属的错误印象；分析文档该轮全写为 Hyper-V 也与 pcapng 不符。

本文件确实表明大部分发现包记录带有 Radmin 源 MAC/IP，且本次样本中 WLAN 源地址未出现。但这**不能推出**“广播统一从 Radmin 网卡发出”、`/8 最长前缀匹配`是已证明根因，或“这是 M0-B Relay 绑定策略硬约束”。pcapng 还出现了单独的 Hyper-V 源记录；当前证据也没有路由快照、接口索引/捕获点元数据与受控路由变更实验。

**修订要求：**将结论限定为“在该主机、该配置、该次抓包中，多数记录显示 Radmin 源，另有一个发现数据报身份显示 Hyper-V 源；WLAN 源未在此样本中观察到”。删除“由 /8 最宽前缀匹配确认”及“对 Relay 绑定是硬约束”。M0-B 绑定设计应以双机 E2 的端到端收发及明确接口绑定实验决定。

## 4. F1、F2 可采信范围

- **F1 有限结论可采信：**本次未注入抓包中，存在 3 组各覆盖 UDP 目的端口 62900–62999 的广播数据报身份，载荷一致；原始记录中存在重复捕获。源地址并非所有身份一致，需按第 3 节修订。此证据不证明其他网络、机器或联机配置行为。
- **F2 负向观察可采信但范围受限：**在该 30 秒单机、未进入对局的窗口，未在捕获中发现对应发现回复；这只能说明本次窗口观察为零回复，不能证明房主在场时回复路径、T_response 或跨机收发。后者仍须 E2。
- 报告 §3.2:163–169 的 SSDP 与 CivLink 发现协议区分，适合作为本次负向观察的排除依据；不能据此宣称正向 F2 已验证。
- `sendmsg`、`紧循环`及无 sleep/yield 属于根据包间隔/端口序列作出的实现推断，不是 pcapng 可直接观测到的 API 调用事实。
