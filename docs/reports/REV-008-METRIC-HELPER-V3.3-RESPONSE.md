## §2 R-3b（阻断项）逐条处置

复核意见：`Set-NetIPInterface -InterfaceMetric` 会自动禁用 `AutomaticMetric`；restore 预检只允许该字段等于 `OriginalAuto`，因此 `OriginalAuto=Enabled` 的 changed 接口在成功 apply 后必然被判漂移，形成不可恢复路径。

官方行为已核实（Microsoft Learn `Set-NetIPInterface`，view=windowsserver2025-ps）：

> `-InterfaceMetric … This parameter value uses the value generated by AutomaticMetric by default. If this parameter value is set, then the AutomaticMetric parameter is automatically disabled.`

### 2.1 允许集合改为字段级（`Get-PrecheckDrift`）

预检逻辑抽成纯函数 `Get-PrecheckDrift`（`param($Backup, [hashtable]$Rows, [scriptblock]$NameDrift)`），不访问网卡，restore 与自测共用同一实现。

| 字段 | apply 是否写入 | restore 允许的现值 |
| --- | --- | --- |
| changed.Metric | 写 `TargetMetric` | `{OriginalMetric, TargetMetric}` |
| changed.AutomaticMetric | 不写，但 setter 会自动置 `Disabled` | `{OriginalAuto, Disabled}` |
| keep.Metric | 写 `TargetMetric` | `{OriginalMetric, TargetMetric}` |
| keep.AutomaticMetric | 写 `Disabled` | `{Disabled, OriginalAuto}` |

- 未为了放行而加入任意 Auto 值：changed 的允许集合只多了 `Disabled` 这一个**由 setter 行为产生**的值，其它值仍拒。
- 接口不存在、keep 记录缺失、读取失败 → 在 `Set-NetIPInterface` 之前 `exit 2`。
- 偏离诊断按 `interface / field / allowed / now / reason` 逐行输出。

### 2.2 备份 schema 3 → 4

`$payload.schema = 4`；`keep` 与每个 `changed` 项新增 `TargetAuto = 'Disabled'`，把"apply 打算把 Auto 变成什么"落进备份，而不是只靠代码隐式行为。

## §3 apply readback 现在核对 AutomaticMetric

- 原来：`Test-Row -idx ... -auto ''`；`Test-Row` 内 `if ($auto) { ... }` 因空串跳过 Auto 比对，脚本从未确认 setter 把 Auto 关了。
- 现在：`foreach ($e in $raise) { Test-Row -idx $e.ifIndex -metric $targetMetric -auto 'Disabled' -label 'raised' }`。
- 同时打印 `recorded target state: changed => (metric=…, auto=Disabled); keep => (…)`，便于把日志与备份允许集合对齐。
- 例外：`OriginalAuto='Enabled'` 的还原方向，Windows 会按链路速度重算 metric，写入值不保留 → restore readback 传 `$metric = $null` 只校验 Auto 标志（`Test-Row` 已支持 metric 为 `$null` 时跳过数值比对）。

### 4.4 未还原备份守卫（顺带修的一个顺序缺陷）

原顺序是"无竞争接口 → NOTHING TO DO exit 0"排在守卫之前，会导致存在未还原备份时 dry run 返回 0、而真实 apply 返回 5（预测与实际不符，正是 REV-006 对 `-DryRun` 语义的要求所在）。

现顺序：`[plan]` → 未还原备份守卫 → NOTHING TO DO → `-DryRun` 早退 → 管理员门禁。

实测：构造一笔未还原 backup 后 `apply -DryRun` → `exit 5`，`[refused] an unrestored apply-backup already exists: civlink-metric-20261112-210000-abcd1234.json`。

## §5 两阶段提交故障注入（只针对文件事务）

- 入口：`-Action tx-selftest`（`[ValidateSet]` 新增该动作）。
- 机制：生产路径的文件操作全部走可注入表 `$script:TxOps`（`OpenCreateNew` / `WriteAllText` / `ReadAllText` / `Hash` / `Move` / `Remove` / `Exists`），自测在**隔离临时目录**逐个阶段注入失败。
- 事务实现：`Invoke-BackupTx` 返回 `{Ok, Stage, Message, Residual, FinalHash}`，阶段序 `json-stage → json-hash → json-verify → sidecar-stage → sidecar-verify → sidecar-commit → json-commit → hash-confirm → done`；失败即回滚并计算 `Residual`（成功时只监视两个临时文件，提交的两个正式文件不算残留）。

实测（exit 0）：

```
 stage            ok  reported  stageSeen        jsonLeft sidecarLeft sidecarValid residual
    json-stage      PASS  True      json-stage       False    False       False        0
    json-hash       PASS  True      json-hash        False    False       False        0
    json-verify     PASS  True      json-verify      False    False       False        0
    sidecar-stage   PASS  True      sidecar-stage    False    False       False        0
    sidecar-verify  PASS  True      sidecar-verify   False    False       False        0
    sidecar-commit  PASS  True      sidecar-commit   False    False       False        0
    json-commit     PASS  True      json-commit      False    False       False        0
    hash-confirm    PASS  True      hash-confirm     False    False       False        0
    cleanup         PASS  True      json-commit      False    True        False        1
    success-path    PASS
```
```
 [precheck] applied(orig=Enabled)=0(0)  foreign metric=1(>0)  applied(orig=Disabled)=0(0)  re-enabled-after-Disabled=1(>0)
[PASS] two-phase commit fault injection + precheck cases
```

- 前 8 个阶段：均报告失败、无正式 apply JSON、无有效 sidecar、无残留。
- `cleanup`（清理也失败）：如实留下 1 个**无效** sidecar 作为残留并计入 `Residual`，同时提示孤儿 sidecar 会被"未还原备份"守卫当成真实锁——这是已知的、有意的诚实失败，不是被吞掉的错误。
- 全部用例均未触碰真实备份目录，也未调用任何网卡修改。
