## 2. 按证据类别裁定

### 源码/文档确认

- 本地 PC-B v3 操作文档明确只改 InterfaceMetric/AutomaticMetric，并将 `Find-NetRoute 255.255.255.255` 定义为弱预测；该文档是实验操作方案，不是执行记录。
- F-2 的类型问题成立：JSON 中数值 `1` 与字符串 `'Enabled'` 不相等，旧的 `-eq 'Enabled'` 分支不能正确识别数值备份。v3 文档描述了兼容数字/字符串的修正；本次没有取得 PC-B 执行文件或完整命令日志来独立复现实际回滚。
- REV-012 当前本地文件为 13,657 B；哈希与上列提交值一致。

### 执行端报告的测试观察（等待原件）

- 修改前 800 个发现签名包呈现 Radmin 源，修改后 600 个游戏包呈现 WLAN 源；自建 300 包也报告为 WLAN 接口收到。
- 这些数据若原始日志哈希复核通过，可支持“该 PC-B 配置修改前后，观测到的本机发现报文来源/接口发生变化”。由于操作同时改变 WLAN 与 Radmin 的多个配置值、没有反向恢复/重复交叉实验，**不证明 InterfaceMetric 是唯一原因，也不证明一般 Windows 广播出口必由最小 metric 决定**。
- 报文到达接口的本机监听记录属于本机报文观测；没有改后 pcapng/独立外部抓包时，措辞应避免扩大成链路级、跨机或产品级证明。

### 负责人提供的房间互见观察

- 双向建房/刷新后互见是项目负责人亲自观察，按 D 级口述采信，可帮助排期，不能替代逐轮记录、H4 原始发现响应/JSON 或 E2-A 审计证据。
- 新五次刷新现象与 metric 修改后单机报文观察构成值得继续验证的线索，但还不是受控因果闭环。

### 推断/未验证

- 两端 Radmin 客户端离线，因此旧 E2-A 的 ping/ARP/tracert 结果只说明当时没有验证出端点间 Radmin 可达；**不能据此断言在线 Radmin VPN 不通或产品必需 Relay**。
