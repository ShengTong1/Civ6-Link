## 1. 直接核对的证据

1. 主运行目录 `M0A/captures/E2B-synthetic-20261113-115258/` 中 `summary.txt` 记载 `99 bound`、跳过 62984、发送 1 次响应、22 页各一次、99 个请求端口、98 个突发窗口内的其余匹配请求。
2. `requests.log` 记载首个本机来源请求 `192.168.31.59:64387` 命中 62900，并向该本机地址回送 22 个 1104 B 页面；每页 SHA256 与 `sent-reply-01..22.bin` 对应。
3. `post-response-traffic.log` 中余下 98 个数据报是同一刷新产生、落在 3 秒合并窗内的发现请求；日志记为不再重复回复。未见脚本对后续流量发出额外响应。
4. `precheck.txt` 记录 UDP 62984 被 `vivoesService_x64` 持有并跳过；62969/62970 是 `::1` 监听，不阻止 IPv4 bind。独立 `probe-burstcount-20261113-113622.log` 记录 62900–62999 每端口一个请求、100/100 到达，首末包时间为 11:36:24.756–11:36:24.864（约 108 ms）。R4 自身的 99 端口记录跨度约 234 ms，因此报告中的“约 86 ms”不应作为本轮 R4 的精确时长；如保留该数字，应注明它来自另一轮测量并复核其首末时间。
5. `client-list-item-observed.png` 可见匿名房间 `CivLink-Test-Room-2222`，规则为风云变幻、盘古大陆、联机、1/6。这个画面与 R4 的本机构造响应记录相互印证。
6. 运行约束证据显示只向请求源本机地址发送、不改网卡/防火墙、不注入 DLL，房间名被替换。故结果符合 REV-013 §4 的单机有限试验授权。

**流量措辞更正**：实验期间 Civ6 客户端按正常发现流程发出了有限广播请求；这是授权实验的一部分，广播可能到达本机 WLAN。Responder 没有向远端发送合成响应。主运行目录 `summary.txt` 中“no packet left this machine except unicast replies”若按整台机器理解并不准确，应解释为“Responder 未向远端发出响应”；后续归档摘要按此更正，原始运行文件保持不改并由本复核注明。

## 2. T-class 工具缺陷定性

接受为 **T-class（实验接收工具缺陷）**：PowerShell `ReceiveMessageFrom` 的 `ref` 出参被脚本级变量跨调用复用；诊断记录表明第二个调用起抛 `MethodInvocationException`，此前 `catch { break }` 将其隐藏。hoist 与 loop-local 对照分别得到 1/99 与 99/99；Responder 修复版和独立探针在可用端口上捕获完整突发。此前据接收日志得出的“Civ6 一次刷新只发 1 包”结论作废。现有直接证据支持本次构建的一次刷新向 UDP 62900–62999 每端口各发一个请求；本轮主运行因 62984 被占用，Responder 本身观察的是 99/99，100/100 来自独立探针。

**不要把根因泛化成“任何监听器都必须排空所有 socket，否则只能收到 1 包”。** 本次已证明的主要故障是 `[ref]` 输出对象复用和未记录异常；每个 socket 是否应在一次 readiness 回调内排空，取决于事件模型及队列语义。生产接收器应保证每个数据报最终可被处理，且每次调用使用有效的输出对象并把非预期异常写入日志/计数器。

## 3. 修复版脚本的残余事项

复核 `scripts/synthetic-host-responder.ps1` v2：接收循环已在调用内创建 `$remoteEp/$flags/$pinfo`，解决本次复现的跨调用引用故障。但通用异常分支仍为 `catch { break }`（约第 239–240 行），没有写错误记录；`SocketException` 也被一概当作队列已空。因此报告中“接收异常不再静默吞”的表述超过源码现状。

该残余不推翻本轮实测完整的 99 端口请求日志、一次响应和 UI 结果，也不改变本次试验符合授权范围的结论；但在脚本再次用于实验前，应将预期的 would-block 与非预期接收错误分开处理，并把后者持久化记录，再用故障注入/回归测试覆盖。此项是工具整改，不要求重做本轮客户端结果。

## 4. pcapng 裁定

不为本轮补 pcapng，不需要额外 UAC。当前授权目标是验证本机客户端是否接受合成公告并显示列表，不是建立链路层因果或网卡归属证据。主证据的逐请求记录、22 个发送页面、哈希、独立 100/100 探针及 UI 截图已覆盖该目标。若今后要确认二层接口、帧级时序或所有发送包确实上线路，再提出独立抓包任务。
