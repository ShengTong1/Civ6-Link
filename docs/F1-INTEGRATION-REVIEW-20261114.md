- 被复核件：`F1-INTEGRATION-SUBMISSION.md`
- 裁定范围：REV-016 F1 的“模拟房主经 DLL/Agent 通道向真实 Civ6 客户端提供公告并显示房间”子项。
- 状态：**限定通过**。
- Gate：Gate A 未批准；正式 M0-B/Gate B 仍未放行。本裁定仅允许继续 F2 非发布原型。

## 1. 独立复核

提交件 SHA-256 重算一致：`B400F7545F61EEBDF1045ECA90C1AA5641842C9F29942D1AA8D65CF09C560FBC`；文件 11,437 B、无 UTF-8 BOM。关联报告、README 和交接文档哈希也与提交件一致。

原始证据中两轮有效运行的数据彼此吻合：

- 第一轮 Hook 计数增量 300；Agent 收到/处理 300；模拟器看到 300 个发现请求，按 3 个逻辑 socket 各发送 22 页，共 66 页；发送失败、绑定失败、超预算均为 0。
- 第四轮 Hook 计数增量 700；Agent 收到/处理 700；模拟器看到 700 个请求，按 7 个逻辑 socket 各发送 22 页，共 154 页；发送失败、绑定失败、超预算均为 0。
- 两轮 Agent 汇总均报告序号连续、无缺口/重复/乱序，目标端口覆盖 62900–62999。对应原始日志及逐页 fixture 文件已在各自证据目录中。
- 两轮机器校验各 9/9 PASS，验证 Hook/Agent/模拟器计数、页数与错误计数。**机器校验本身不读取游戏 UI**；“房间出现在 Civ6 列表”由负责人在 m14428、m14466 两轮直接观察并报告。此部分按负责人观察采信，不伪称由自动化截图断言。

void 轮次收到 0 帧，前后 Hook 计数不变，故能排除“窗口内已捕获但 Agent 漏收”。窗口结束时间早于报告给出的刷新指令时间；接受其为**实验窗口与操作者操作错位**，不计为产品失败。指令送达时间依执行记录采信，不属于原始机器日志独立证明的事实。

## 2. 允许的限定结论

> 在本构建和本机环境中，DLL 捕获 Civ6 的发现请求并经本机 CVLH2 通道交给模拟房主 Agent；Agent 从本机选定的地址和 `62900` 源端口向 Civ6 临时端口发送 fixture 公告。负责人两次观察到真实 Civ6 客户端列表显示 `CivLink-Test-Room-2222`。第一轮 3 个刷新 socket 各发 22 页，第四轮 7 个刷新 socket 各发 22 页；Hook、Agent、模拟器计数闭合。

此结果证明的是**单机真实游戏客户端 + 本机模拟房主**的发现集成路径。回复由模拟 Agent 直接发送给游戏客户端；它没有经 Hook 回送，不是远端 Peer、Relay 或真实房主。源地址 `26.74.126.98` 是本次运行配置，不证明 WLAN、Radmin 隧道或任意虚拟 LAN 的远端可达性。

## 3. 明确不证明的事项

- 两台真实 Civ6 电脑互相发现、加入或完成对局；
- 62056 游戏数据面、Fake-IP 映射或 Relay；
- WLAN/Radmin/其他 VPN 间的直连选择或跨网能力；
- 多次刷新以外的长时间稳定性、不同构建兼容性；
- Gate A、Gate B 或正式 M0-B 验收通过。

F1-live 的 Hook 观测子项此前已单独限定通过；结合本次集成子项，**REV-016 的 F1 两个子项现可记为“限定通过”**，不扩大项目 Gate 状态。

## 4. F2 裁定与切换前置

**批准开始 F2 非发布原型的设计与实现**，范围限定为 Fake-IP 会话映射和 62056 数据面模拟验证，继续使用模拟 Peer，不要求第二台 Civ6 电脑。

开始改 Hook DLL 前：

1. 对当前 Civ6 进程执行 `CivLinkShutdown` 并保存状态/计数回读；
2. 按 B2 审计运行模式，Hook DLL 会保持映射，不能在进程存活时覆盖/重链该 DLL；因此应正常退出 Civ6，确认进程结束后再构建并启动新测试进程；
3. 新的 F2 测试仍区分“模拟数据端通过”和“两个真实 Civ6 完成游戏对局”。

F2 设计必须纳入：每次刷新创建新 socket；首帧 `0.0.0.0:0` 不是有效 Peer 端点；`sendto` 观察结论限本次构建和发现路径；Hook→Agent 同步本机发送在队列满、Agent 不在和高负载情况下的延迟/失败影响须有测试。
