## §1 目标与需求映射

### 1.1 问题背景（项目实测结论，来自 METRIC-PRECONDITION-20261113.md）

- Windows 把 `255.255.255.255`（limited broadcast）当作一个目的地址做路由选择：每个网卡各有一条 `255.255.255.255/32` 的本地等价路由（Protocol=Local，RouteMetric=256，InterfaceMetric=<该网卡值>），**取 InterfaceMetric 最小者对应的接口**作为出接口。
- 实测表（PC-A）：Radmin VPN if21 metric=1、WLAN if11 metric=45、loopback if1 metric=75、ZeroTier if16 metric=1045、WSL if58 / DefaultSwitch if18 metric=5000。
- B 机曾因 Radmin VPN metric=1，发现广播全部从 Radmin 网卡发出，A 机（在 WLAN 侧）收不到；手工把 Radmin metric 调到 200 后恢复——但这是**系统级**设置，影响该机器上所有进程，且跨重启/重装会漂移。
- 结论：需要**进程级**定向，只影响 B 的游戏进程，不动系统配置。

### 1.2 C2 交付目标

| 编号 | 目标 | 验收判据（机械证据） |
|---|---|---|
| C2-G1 | B 机游戏进程的发现广播从 `--iface <IP>` 指定网卡发出 | 自检 §7：指定网卡发包计数增量 ≥ N，其余网卡 ≈ 0 |
| C2-G2 | `--iface ALL`（默认）时零干预，广播仍走 metric 最小接口 | 自检：pinned==0，metric 最小接口计数增量 ≥ N |
| C2-G3 | 不吞包/不改载荷/不改系统配置 | 断言：sendto 返回值不变、DLL 计数器 pinned 语义正确、无任何 socket 选项被改除 IP_UNICAST_IF |
| C2-G4 | 工具链复用：status/counters/shutdown 对两个 DLL 通用 | ctl `-m` 参数覆盖模块名 |

### 1.3 三态语义（--iface）

| 配置 | 语义 | 行为 |
|---|---|---|
| `--iface ALL`（默认，含未配置） | 全网卡不干预 | 注入物不设置 IP_UNICAST_IF，纯透传；广播按 Windows 默认（metric 最小接口）发出 |
| `--iface <IP>` | 严格定向 | 注入物对发现目标发送前设置 IP_UNICAST_IF=该 IP 所属接口索引，广播从该网卡发出 |
| 配置无效（非本地 IP / 接口 down / 格式错） | 降级 | 注入器（ctl）**fail-closed**：写配置前本地预校验，非本地 IP 拒绝注入（exit 1）；注入物（DLL）**fail-open**：initError=11/12 记录原因后以 ALL 模式继续透传（绝不影响游戏运行） |

## §2 机制背景：Windows 广播出接口选择

### 2.1 255.255.255.255 的路由行为（已实测 + 外部佐证）

1. `255.255.255.255/32` 在每块网卡上各有一条本地路由（`route print` 可见），Windows 用"最具体路由 + 最小 InterfaceMetric"挑选出接口，即**只从一块网卡发出**。
2. 外部佐证：WinIPBroadcast（github.com/dechamps/WinIPBroadcast，GPL，450 行）README 明确写道："Windows 7 only sends global IP broadcast packets (destination address 255.255.255.255) on the interface which matches the preferred route for 255.255.255.255 in the route table." 其存在的全部意义就是解决"广播只走一块网卡"的问题。
3. 项目 E1 实测：对 socket `bind(192.168.31.59)`（WLAN IP）后发广播，100/100 从 WLAN 发出——**绑定源 IP 能绕开系统路由选择**，且不动任何系统配置。这是方案 B 可行性的最强前置证据（IP_UNICAST_IF 与 bind 源 IP 作用于同一套"出接口选择"机制，见 §3.2）。

### 2.2 为什么进程级定向可行

- Winsock 每 socket 可独立设置 `IP_UNICAST_IF`（IPPROTO_IP 层选项），**只影响该 socket 的出向流量选择**，不改变系统路由表、不改变其他进程、不改变接口 metric。
- 该选项在 socket 首次发送（含隐式 bind）前设置即可生效，游戏进程无需感知。
- 因此"让 B 游戏进程的发现广播从指定网卡发出"可完全在进程内、以注入方式实现，无需管理员权限、无需改动系统。

### 2.3 关键修正：IP_UNICAST_IF 的选项编号

> ⚠️ 修正 M0C-DUAL-ROLE-PLAN §3 及用户提示中的"setsockopt 第 25 项"：**IP_UNICAST_IF 的数值是 31，不是 25**（25 是 IP_RECVDSTADDR）。依据：mingw-w64 与微软 SDK 的 `ws2ipdef.h` 定义（`IP_RECVIF=24, IP_RECVDSTADDR=25, ... IP_UNICAST_IF=31`，已用 mingw-w64 官方头文件镜像核实）。

## §3 技术方案对比与选择

### 3.1 方案总览

| 方案 | 做法 | 影响面 | 管理员 | 优点 | 缺点 |
|---|---|---|---|---|---|
| A（系统级 metric） | `Set-NetIPInterface -InterfaceMetric` 或注册表调整 | 全系统所有进程 | 是 | 实现最简单 | 系统级副作用、跨重启漂移、B 机已手工做过（200）仍不彻底；用户已否决（需求为进程级） |
| B（主，socket 定向） | sendto/WSASendTo 前对发现目标 socket 设 `setsockopt(IP_UNICAST_IF, ifindex)` | 仅游戏进程内该 socket | 否 | 精确、无系统副作用、与 E1 实测机制同源 | IP_UNICAST_IF 对 broadcast 的适用性需实测（§3.2 标注） |
| C（兜底，复制转发） | 定向网卡广播不可达对端时，把原广播包**复制**一份从定向网卡再发（不篡改原包） | 仅游戏进程 | 否 | 可覆盖"定向不生效"场景 | 双份广播、与 WinIPBroadcast 同机制（RAW socket 监听 loopback 再转发，有 src==dst 端口限制）；复杂度高 |

**结论：方案 B 为主实现，方案 C 仅设计（先实现 B，实测验证后再决定是否值得实现 C）。**

### 3.2 方案 B 细节：IP_UNICAST_IF 的准确用法

**MSDN 原文语义**（learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options，已抓取核实）：

> "Gets or sets the outgoing interface for sending IPv4 traffic. This option does not change the default interface for receiving IPv4 traffic. … The input value for setting this option is a 4-byte IPv4 address in network byte order. This DWORD parameter must be an interface index in network byte order. Any IP address in the 0.x.x.x block (first octet of 0) except IPv4 address 0.0.0.0 is treated as an interface index. … An interface index is a 24-bit number. … The GetAdaptersAddresses function can be used to obtain the interface index information. If optval is zero, the default interface for sending traffic is set to unspecified."

要点提取：
1. 取值：**network byte order 的 4 字节接口索引**（不是主机序 DWORD；`htonl(ifIndex)` 后传入）。
2. 描述为 "outgoing interface for sending IPv4 traffic"——**并未限定 unicast**（名称带 UNICAST 但语义是"IPv4 出向流量"）；但 MSDN 未显式给出 broadcast 用例，**对 broadcast 是否生效属"需实测验证"**（见 §3.3 验证方法）。
3. 支持 Vista/Win7 起（XP/2003 不支持）——目标机为 Win10/11，无兼容问题。
4. `optval=0` 恢复默认（本设计用于 ALL 模式的显式兜底，但默认不设置）。
5. 该选项在 bind 前调用时，到 bind 时才检查（MSDN setsockopt 页）；未 bind 的 UDP socket 首次 send 会隐式 bind → 在 sendto detour 中**每次发送前**设置是安全且必然生效的时机。

```cpp
// 在 sendto/WSASendTo detour 内、调用 Real_sendto 之前：
static void PinSocketIface(SOCKET s, const sockaddr* to, int tolen, int flags) {
    if (g_pinIfIndex <= 0) return;              // ALL 模式：不干预
    if (!IsDiscoveryTarget(s, to, tolen, flags)) return;  // 仅发现目标
    if (SlotIsPinned(s)) return;                // 每 socket 只设一次
    DWORD ifIdxBe = htonl((DWORD)g_pinIfIndex); // ← network byte order，4 字节
    int rc = setsockopt(s, IPPROTO_IP, IP_UNICAST_IF,
                        (const char*)&ifIdxBe, sizeof(ifIdxBe));
    if (rc == 0) SlotMarkPinned(s);             // 成功 → 记 pinned
    else         g_counters.sendFail++;         // 失败 → 计数，仍透传（不吞包）
    // 注：setsockopt 不是被 hook 的函数 → 无重入问题；SRWLock 保护 slot，不覆盖整个调用
}
```

**接口索引解析（权威：GetAdaptersAddresses）**：

```cpp
// 返回指定 IPv4（点分字符串）所属接口的 IfIndex；未找到返回 0
static int ResolveIfIndexForIp(const char* ipStr) {
    DWORD bufLen = 15 * 1024;
    for (int attempt = 0; attempt < 3; attempt++) {
        std::vector<BYTE> buf(bufLen);
        PIP_ADAPTER_ADDRESSES aa = (PIP_ADAPTER_ADDRESSES)buf.data();
        ULONG rc = GetAdaptersAddresses(AF_INET, 0, nullptr, aa, &bufLen);
        if (rc == ERROR_BUFFER_OVERFLOW) continue;
        if (rc != NO_ERROR) return 0;
        for (PIP_ADAPTER_ADDRESSES p = aa; p; p = p->Next) {
            // 仅接受 OperStatus == IfOperStatusUp 的适配器（接口 down → 视为配置无效）
            if (p->OperStatus != IfOperStatusUp) continue;
            for (PIP_ADAPTER_UNICAST_ADDRESS u = p->FirstUnicastAddress; u; u = u->Next) {
                if (u->Address.lpSockaddr->sa_family != AF_INET) continue;
                const sockaddr_in* si = (const sockaddr_in*)u->Address.lpSockaddr;
                char ip[INET_ADDRSTRLEN];
                inet_ntop(AF_INET, &si->sin_addr, ip, sizeof(ip));
                if (_stricmp(ip, ipStr) == 0) return (int)p->IfIndex;
            }
        }
        return 0; // 地址不本地 → 未找到
    }
    return 0;
}
```

**交叉校验（可选，GetBestInterfaceEx）**：`GetBestInterfaceEx((SOCKADDR*)&sin, &idx)` 传入该 IP 本身，返回结果应与 GetAdaptersAddresses 一致（对本地地址二者应一致）；若不一致，**以 GetAdaptersAddresses 为准**并记录到计数器/日志。注意：`GetBestInterfaceEx` 传入 `255.255.255.255` 会返回 metric 最小接口（即当前广播出口），**不能**用于定向目标解析——定向目标必须来自 --iface IP 的属主接口。

### 3.3 对 broadcast 适用性：判定与验证方法

**判定结论：需实测验证（不确定项）**，理由：
- MSDN 描述（"outgoing interface for sending IPv4 traffic"）不排除 broadcast，且与 E1"bind 源 IP → 广播 100/100 走该接口"的实测同属出接口选择机制 → **倾向有效，置信度中高**。
- 但无任何权威来源给出"IP_UNICAST_IF 作用于 limited broadcast"的直接用例；选项名含 UNICAST，存在 Windows 仅对 unicast 查该选项的可能 → **必须实测**。

**验证方法（实测步骤，纳入 §7 自检）**：
1. 本机双接口计数法（无需管理员）：B 机现状 WLAN metric 45 + Radmin metric 200（metric 最小 = WLAN）。
   - pin=WLAN：发 N 个 `255.255.255.255:62900` → 断言 WLAN 接口 Packets Sent/sec 增量 ≥ ~N、Radmin ≈ 0；
   - pin=Radmin（反向对照）：断言 Radmin 增量 ≥ ~N、WLAN ≈ 0；
   - 控制组（ALL 无 pin）：断言 WLAN（metric 最小）增量 ≥ ~N、Radmin ≈ 0。
2. pktmon 逐接口抓包法（需管理员）：`pktmon start --etw -p 62900`（或 filter 端口 62900）→ 发包 → `pktmon stop` → 检查哪些接口捕获到 `255.255.255.255:62900` 出包。这是最强的机械证据。
3. 结论若为"IP_UNICAST_IF 对 broadcast 无效"→ 启用方案 C（§3.4）作为主路径；若有效 → C 仅保留为可选兜底。

### 3.4 方案 C 设计（兜底，先设计后定实现）

- 触发条件：B 定向成功（pinned 计数正常）但目标网卡上无对端应答 → 仅在**需要跨网卡双发**的场景启用（默认关闭，配置开关如 `client-iface.txt` 第二行 `DUPLICATE=1`）。
- 机制（WinIPBroadcast 同型）：RAW socket 监听 loopback，捕获本机发出的 `255.255.255.255:62900-62999` 广播，复制并从定向网卡再发一份；原包不改、原出口不拦。
- 已知限制（WinIPBroadcast README）：src==dst 端口相同时 loopback 捕获不到（"cannot see packets where source and destination ports are identical"）——本项目发现包 src 端口为 54322 等随机高位端口、dst 为 62900+，**不冲突**，但需实测。
- 工作量与风险：RAW socket + 逐包复制 + 双份广播（带宽/对端重复接收）→ **先实现 B 并实测；仅当 B 实测失败时才实现 C**。本文档至此为 C 提供完整设计基线，不再展开实现细节（留待决策后补）。

### 4.2 socket 身份表（复用 SlotBoundPort 思想）

```cpp
// 表结构：64 槽，SRWLock 保护；与 hook.cpp 的 g_sockSlots 同构，字段裁剪
struct SocketSlot {
    SOCKET  s;
    uint32_t id;        // LogicalSocketId 单调递增
    uint16_t gen;       // 复用代
    bool     used;
    bool     pinned;    // ← C2 新增：该 socket 已设置 IP_UNICAST_IF
    uint16_t boundPortBe; // 曾 bind 的端口（大端），供 IsDiscoveryTarget 身份规则使用
};
```

- `SlotLookup/ForgetSocket/SlotSetBoundPort/SlotIsPinned/SlotMarkPinned`：与 hook.cpp 同风格（SRWLock，短临界区；setsockopt **不在锁内**调用，见 §3.2 代码注释）。
- **线程安全**：多个游戏线程可能并发向同一 socket 发发现包 → 首次并发时可能重复调用 setsockopt（幂等，值相同无害）；`pinned` 标记保证正常路径只设一次；`g_pinIfIndex` 在 InitThread 一次写入、之后只读，无需原子（用 `std::atomic<int>` 亦无妨）。
- **生命周期语义（文档化为边界）**：socket 一旦被 pin，其**整个生命周期**内所有发送（含后续非发现发送）都从该接口发出。理由：发现 socket 的用途就是与该接口上的房主通信，socket 不会跨网卡复用；此行为可接受。若实测发现游戏复用 socket 做多网卡通信，再评估"按包 pin/解除"（每发送前 set、非发现发送前 set 0）方案。

### 4.3 计数器与 initError 语义（复用 CivLinkCounters，字段映射）

> 结构体 `CivLinkCounters`（civlink_hook.h，#pragma pack(8) POD，全 8 字节字段）**原样复用**，magic/version/sessionId 不变 → civlink_ctl `counters` 命令（magic 校验 + 字段打印）对两个 DLL 通用，无需改动读取端。

| 字段 | C2 客户端语义 |

### 4.4 关键流程

```
InitThread:
  1. WSAStartup（失败 → initError=1，退出线程，state=-1）
  2. 读取配置（§5）→ g_mode (ALL|PIN)、g_pinIfIndex
  3. 若 PIN 模式：ResolveIfIndexForIp → 0/找不到/down → initError=11/12，降级 g_mode=ALL
  4. MH_Initialize → 6×MH_CreateHook → MH_EnableHook（失败 → initError=3/4..10）
  5. g_state = 1（成功）或 -1（失败但 DLL 已映射，不卸载）

sendto/WSASendTo detour:
  1. g_inFlight 计数 + g_tlsInHook 防重入
  2. 计数器 raw*
  3. PinSend(s)  ← 仅发现目标 + PIN 模式；每包 setsockopt，保存/恢复 last error
  4. 调用 Real_sendto/Real_WSASendTo（**在 in-flight 窗口内**，返回值原样返回，绝不吞包）
  5. tlsInHook 复位 + g_inFlight 递减（审计 H-1）

closesocket detour: ForgetSocket；bind detour: FindOrCreateSlot + SlotSetBoundPort；recvfrom 系: 纯计数器
```

## §5 配置传递设计

### 5.1 文件

- 路径：`%LOCALAPPDATA%\CivLink\client-iface.txt`（用 `GetEnvironmentVariableA("LOCALAPPDATA")` 展开；目录由 ctl 在写文件前 `CreateDirectoryA` 确保存在）
- **覆盖变量（正式特性，审计 H-3 登记）**：环境变量 `CIVLINK_CLIENT_IFACE_FILE` = 绝对路径时优先于默认路径，DLL 与 ctl 读同一个变量（实现见 `BuildConfigPath` / `WriteClientIfaceConfig`）。**用途与限制**：自测与便携部署；因为 DLL 在**游戏进程内**读配置，从 shell 设的变量不会传给已注入的游戏进程，正常部署必须走默认路径。ctl 会打印最终生效路径与 `resolved by: env override / default`。
  - **现场实证（2026-11-18 09:16，`C2-inject-smoke-20261118-0916`）**：把 shell 的 `CIVLINK_CLIENT_IFACE_FILE` 指向 PIN 192.168.31.60 后注入真实进程，读回 `initError=0 / sent=0 / ignored=14`——DLL 在目标进程里回落默认路径、读到 `ALL`，**配置看似成功而定向完全未生效**。改走默认路径后同一注入得到 `sent=10 / ignored=4`。因此**正式部署只允许默认路径**，本变量仅作自测/便携用途（见 `docs/M0C-C2-INJECT-SMOKE-20261118.md` §3）。
- 格式：**单行 ASCII**，UTF-8/无 BOM；允许尾随换行与空白
  - `ALL`（大小写不敏感）→ 全网卡不干预（默认）
  - 点分 IPv4，如 `192.168.31.59` → 严格定向
  - **`IFINDEX:<n>`（诊断 token）**：直接按裸接口索引定向，跳过 IP 解析。仅供自测/支持诊断（用于证明非法索引可被观测）；正常部署不要使用
  - 任意其他内容 / 多行（除第一行外忽略）→ 视为无效 → initError=11 + 降级 ALL
- 读取时机：DLL `InitThread` 启动时读一次（游戏进程启动注入后立即生效）；**运行中改配置不生效，需重注入**（文档化为边界，符合注入物"一次读取"模型）
- 异常处理：
  - 文件缺失 / 打开失败 / 空文件 / 全空白 → **ALL 默认透传**（不视为错误，initError 保持 0）
  - 内容非 ALL 且 IP 解析失败 / 非本地 / 接口 down → initError=11/12，降级 ALL（fail-open：绝不让游戏进程不可用）

```cpp
// 读取示例
static int LoadConfig(int& mode, int& pinIfIndex) {
    mode = 0; // 0=ALL, 1=PIN
    char path[MAX_PATH];
    GetEnvironmentVariableA("LOCALAPPDATA", path, MAX_PATH);
    strcat_s(path, "\\CivLink\\client-iface.txt");
    FILE* f = fopen(path, "rb");
    if (!f) return 0;                       // 缺失 → ALL（正常）
    char line[128] = {0};
    size_t n = fread(line, 1, sizeof(line)-1, f);
    fclose(f);
    // 去首尾空白
    trim(line);
    if (line[0] == 0) return 0;             // 空 → ALL
    if (_stricmp(line, "ALL") == 0) return 0; // ALL
    if (inet_pton(AF_INET, line, &addr) != 1) return 11; // 无效 IP → 11
    int idx = ResolveIfIndexForIp(line);    // §3.2
    if (idx <= 0) return 12;                // 非本地/接口 down → 12
    mode = 1; pinIfIndex = idx;
    return 0;
}
```

### 5.2 写文件（civlink_ctl 侧）

- 写入时机（**已按审计 H-3 更正**）：`inject-client` **先做全部校验（`--iface` 预校验 + `ResolveTarget` 找到目标进程）**，两者都通过后**在真正注入之前**写文件。这样无效参数/找不到进程时不会留下半配置；实测 T2/T3 用 `-p $PID -d civlink-no-such-dll.dll` 验证「目标存在 → 配置已写 → 注入阶段才失败」的顺序。
- 写入内容：`--iface` 原值（`ALL` 或 IP 字符串）一行。
- 失败处理：文件写入失败 → 拒绝注入，exit 1（fail-closed at ctl），并打印 `errno=` / `lastError=`。
- 路径解析打印：写前打印 `[*] client iface config path:` 与 `[*] resolved by: env override (CIVLINK_CLIENT_IFACE_FILE)` / `default (%LOCALAPPDATA%\CivLink)`，并提醒「DLL 在**游戏进程**内读配置，shell 里的覆盖变量不会传进去」（审计 H-3）。
- 遗留文件：多次注入覆盖写，无需删除逻辑；改回 ALL 只需重新注入 `--iface ALL`。

## §6 civlink_ctl 改动

### 6.1 新子命令：inject-client

```
civlink_ctl inject-client -x <进程名|PID> [-d <dll路径>] [-w <等待秒>] [--iface <IP|ALL>]
```

流程（**已按实现更正**，审计 H-3/H-4）：
1. 解析 `--iface`（默认 `ALL`）。
2. 若为 `<IP>`：`ResolveIface`（GetAdaptersAddresses + OperStatus==Up + inet_pton）；**非本地 IP / 接口 down → 打印错误，拒绝注入，exit 1**（fail-closed）；**loopback（`IfType == IF_TYPE_SOFTWARE_LOOPBACK`）同样拒绝**并打印 `loopback is not a real egress choice; use ALL or a physical/virtual NIC`；通过则打印 `[+] interface selected: <FriendlyName> (IfIndex=N IfType=N metric=N)`。

5. 退出码沿用现有约定（0 ok / 1 前置失败 / 2 目标未找到 / 3 模块未加载或 PE 身份不符 / 4 远程调用失败 / 5 状态未达）。

### 6.2 工具链复用：`-m <dllname>` 参数
- `status / counters / shutdown` 增加可选 `-m <dllname>`，默认 `civlink_hook.dll`；`inject-client` 隐含 `-m civlink_client.dll`。
- **自动探测（2026-11-18 09:23 新增，见 `docs/M0C-C2-INJECT-SMOKE-20261118.md` §4）**：未显式给 `-m` 时，若目标进程里查不到 `civlink_hook.dll` 而查得到 `civlink_client.dll`，自动改用后者并打印 `[*] target has civlink_client.dll loaded - using it (override with -m)`。原因：`status`/`counters` 用 `g_dllName` 在**本地**解析导出 RVA，默认名对 client 注入的进程会报 `cannot resolve CivLinkHookState` exit 1，用户会读成"注入失败"。

## §8 边界与证据纪律

1. **机械证据 ≠ 双人验证**：本轮 §7 自检**只到"记账层"**——证明计数器语义自洽、未破坏发送层、fail-open/fail-closed 路径可达；**尚未证明**"广播从指定网卡发出"（该命题需跨机抓包/逐接口计数，见 §7.2/§7.3 第 4 项，登记为 **uncovered**），更**不证明** A/B 双人联机可发现可加入。E2-A / E2-B / E3 勾选不在 C2 范围，且在跨机实测与真实 Civ6 进程内验证完成前，**不得把 C2 表述为"已验证"**。
2. **只读纪律（C2 硬约束）**：
   - 绝不吞包、绝不改载荷、绝不复制包（方案 B 主路径下）；
   - 绝不转发 62056 数据面；agent 永不 bind `0.0.0.0:62056`、永不 SO_REUSEADDR（沿用 C1 已确立约束）；
   - 唯一对 socket 的改动：发现目标上的 `setsockopt(IP_UNICAST_IF)`，且仅 PIN 模式；**必须保存并恢复 `WSAGetLastError()`**（审计 B-2，成功/失败两条路径），否则会污染应用可见的 last error。
3. **不动系统**：不写 metric、不改路由表、不写注册表、不需管理员（pktmon 抓包仅自检可选）。
4. **fail 语义**：ctl fail-closed（无效 --iface / loopback 拒绝注入）／ DLL fail-open（任何异常降级 ALL，游戏照常）。
5. **已修正的错误**：IP_UNICAST_IF 数值为 **31**（非用户提示与计划中的"25"）；文档以本节为准。
6. **不确定项（需实测）**：
   - IP_UNICAST_IF 对 limited broadcast 的适用性（**未验证**；§3.3 方法；本机回环实验中广播不回环到绑 0.0.0.0 的 socket，故本机无法回答，必须跨机）。
   - `setsockopt` 对**越界接口索引**在 Windows 上返回 0（接受），因此"非法索引→失败"的假设**已被实测推翻**（场景 H）。
   - 每包 setsockopt 相对"只 pin 一次"的性能代价（~1µs/包，发包量级 100 包/次刷新，可忽略），但未做长跑测量。
   - 「pin 后隐式 bind 是否清除该选项」未得到权威结论，故实现选择每包设置（审计 M-6 的建议方向）。
