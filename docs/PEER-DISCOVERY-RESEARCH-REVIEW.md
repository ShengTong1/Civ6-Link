# PEER-DISCOVERY-RESEARCH 技术审计

审计对象：`PEER-DISCOVERY-RESEARCH-20261120.md`（188 行）。仅审计，未改任何产品代码。

## 0. 总裁定（摘要）

**有条件通过。** 报告事实基本可核验、三分法大体诚实、未越界宣称双机可用；但存在 1 个硬冲突：推荐 socket2/if-addrs 与 agent「零依赖 + `--offline`」硬约束直接矛盾（§6），另有 4 项必改（事实标注升级过度、评分权重漏标、开放问题漏项、bind IP 与 IP_UNICAST_IF 主次不清）。修完必改项方可进入实现。

## 1. 来源支撑核验

- **可核验（已本地核实）**：SO_BROADCAST 实验 `docs/diagnostics/a6-sobroadcast-experiments/README-A6.md` L18-25 确有 c4/c5/c6 矩阵（全局广播 10013、定向广播成功、optlen<4+val=1）；Low IL 证据 `prototype/PHASE0-FORENSIC-RESULT.md` L6-11、L78-84 确有 0x80041003 及「仅 Find-NetRoute 这一条 CDXML 失败、非所有 WMI」的限定。均可独立复核。
- **报告自述归档、本次未逐条打开**：RFC 5357/3550/6812/8882、WinIPBroadcast、CERT VU#550620、MSDN SO_REUSEADDR。§9 仅称「已归档在会话记录」，§2/§3 正文未列 URL，读者无法独立核验（建议就地挂链接/路径）。
- **标注瑕疵**：§2.2 把「Windows 全局广播只走首选接口」写成纯【事实】，其实 WinIPBroadcast 项目 README 是该行为的主要证据（间接/经验性），微软文档未直接承诺「只走首选接口」，宜降为【事实（第三方项目动机佐证）+需实测】。
- **夸大**：§2.2 称 injciv6「证明广播→单播重定向成熟，也反证游戏侧广播不可靠」——单个 ~207★、无 License 项目只能证明「有人这么做」，不能证明成熟；「反证游戏侧广播不可靠」是推断，被标为【事实】。
- **正确**：TWAMP RTT 免同步、RFC3550 抖动/序号丢包、SO_REUSEADDR 劫持均与标准一致，无错误。Rust TWAMP「只有 0.1.0 早期版」缺来源，宜注明「检索时点快照」。
- 未发现把明确【推断】冒充【事实】的严重事件（injciv6、全局广播两处除外）。

## 2. 方案自洽性

- **与三项决策一致**：独立新模式 ✓（`--peer-discover`）、两阶段 ✓（MVP 只展示不切换）、私有 UDP ✓。张力：§2.3「mDNS 可选兼容层」与「不上 mDNS」措辞冲突，应注明不属 MVP。
- **bind IP vs IP_UNICAST_IF 主次不清**：§2.3 推荐 `bind(本地IP:0)`，§3.2 又写「bind 源 IP 是事实标准；IP_UNICAST_IF 兜底」，易读成两者都要实现。socket2 的 `bind_device_by_index_v4` 在 Windows 就是 bind IP，非并列要求。需明确：主=每网卡 bind 本地 IP；IP_UNICAST_IF 仅 FFI 兜底、需实测。
- **端口描述有误**：§5 把 34718 写成「agent IPC」；核对 `CivLink-联机方案设计.md` L74/L88，实为**本地/服务器数据面**。63010/63011 与现有端口（62900–62999、62056、34718、47584）不冲突且标「待确认」，处理正确。
- 评分权重合计 1.00 自洽；周期 2–5s 与「频率≥1s」不冲突。但归一化基准与 stability_penalty 未定义，不可直接实现。

## 3. 事实/推断/需实测标注诚实性

- **总体诚实**：§6 把「同链路判定」「token 强度足够」「session_token 风险可接受」标【推断】，同链路阈值/双端数值标【需实测】，未包装成标准结论；§3.3「只能定性分级、不宣称精确值」克制。
- **缺陷 1**：**评分权重（0.45/0.20/0.20/0.10/0.05）及其硬门槛（3%/150ms/10%）在 §6 三分表中完全缺席**。这是本项目自创、无标准依据、直接决定推荐结论，必须补标【推断/需实测】，否则读者会当成已验证结论。
- **缺陷 2**：§1 硬边界写「agent 永不 bind 0.0.0.0:62056」，但 §2.3/§5 监听/过滤细节未声明新端口的 bind 策略；应在设计里明确新端口的监听地址（含是否 0.0.0.0），避免与硬边界表述产生歧义。
- **缺陷 3**：§4.2「SO_REUSEADDR 无需特权即可强绑端口」被定为【事实】；Windows 上 SO_REUSEADDR 的语义与 BSD 不同（MSDN 警告其允许劫持），说法方向正确但需精确化（同一端口不同场景结论不同）。
- 未见把模拟/单机证据写进「事实」栏的严重错误。

## 6. 零依赖约束可实现性（重点）

- **硬冲突确认**：`CivLink-M0A-audit/civlink/agent/Cargo.toml` L9-11 注释明确「Zero dependencies on purpose… buildable with `cargo +1.75.0 build --offline` on a machine with no crate cache」，`[dependencies]` 为空。报告 §2.1/§2.2/§2.3 却把 socket2 0.6.5、if-addrs 0.15.0、network-interface 2.0.5 当作推荐依赖。核对 socket2 0.6.5 依赖 `libc ^0.2.172` + `windows-sys >=0.60,<0.62`——引入它即破坏零依赖与无缓存离线构建。**报告未提及此冲突，是本报告最实质的遗漏。**
- **结论**：按现状方案不可实现。实现前必须先裁决：要么为 agent 破例开依赖白名单（需用户拍板，且违背「零依赖+离线」硬约束，不建议），要么走纯 std + 手写 FFI 路径。
- **可行的替代路径（建议写进报告）**：
  1. 网卡枚举：`std::net` 无枚举 API。用 `unsafe extern "system"` 手写 FFI 调 `GetAdaptersAddresses`（iphlpapi.dll，GAA_FLAG_INCLUDE_PREFIX），或退一步调用 `GetIpAddrTable`；无需新增 crate。 struct 布局需按 Windows SDK 手写，注意 /MT 与 ABI。
  2. 定向广播/绑定出口：每卡 `std::net::UdpSocket::bind("本地IP:0")`，SO_BROADCAST 用 `setsockopt` FFI（ws2_32）设置；可选 IP_UNICAST_IF / IP_PKTINFO 同样 `setsockopt` FFI。socket2 提供的只是这些调用的薄封装，std + FFI 完全可替代。
  3. 时间戳：`std::time::Instant`（单调），无需 crate。
  4. 仍应遵守 agent 现有 `--offline` 构建与无 crate 缓存前提；FFI 代码需集中封装、配最小单元测试。
- 报告 §2.2 已诚实写明「socket2 无 IP_UNICAST_IF 具名包装」，但未把「零依赖冲突」上升为开放问题——应补入 §7 作为**前置裁决项**：依赖白名单 vs 纯 std FFI。
