# M0-G Peer Discover 设计审计

> 对象：`docs/M0G-PEER-DISCOVER-DESIGN-20261120.md` v1.0（冻结）。仅审，未改产品文件。2026-11-20。

## 裁定：NOT PASS

A 组与标注诚实扎实、核心公式方向正确、前序必改基本落实；但 6 项必改中 M2/M3 是"照文档直译即产生错误结果"的真 bug，M4/M5 使安全裁决#4防线落空。须设计层实质修正后重审。必改 B组4/C组2/D组1；通过项 A全部、B4、C2、D3。

## A 需求覆盖
- A1 通过：四点需求逐条落 §1 目标1-4；§1非目标+§7明"只展示不切换"，无越界自动切换。ZeroTier标【需实测】与研究一致。
- A2 通过：六裁决全体现——独立模式+互斥(§2)、按钮触发(§1/§8)、无口令+声明(§1/§5/§8)、默认物理网卡(§2/§9)、只展示(§7)、依赖路线(§3)。

## B 技术正确性
- B1 必改：§5过滤依赖"接收socket绑定网卡"，§9却写"或统一select/poll"，通配时过滤无处落地。改成逐网卡bind该卡IP:63010并补§2监听策略；补【需实测】Win绑定具体IP收定向广播+防火墙。算法ip|!mask本身正确(两例对)，须写明完整32位掩码取反；IP_UNICAST_IF兜底(前序M4)建议补。
- B2 必改：§6字段t4=反射回包戳，公式却用t4′=本地收包戳(不同时钟域)。改成删t4字段+符号表T1/T2/T3/T4′，公式rtt=(T4′−T1)−(T3−T2)(公式本身正确)。建议明确T1拷回+seq(u16)回绕。
- B3 通过：RFC3550 A.8公式正确，建议标s=T1/r=T4′同域。丢包2s窗口方向对，但须写明乱序包缓存、窗内到达计入、超时才计loss；100包/路径仅定性分级(p≈1%需~1.5万包)，loss>3%仅3包统计弱须标注。
- B4 通过：权重=1.00✓、越小越优✓、p50/100ms与p95/150ms标【推断】✓、硬门槛3%/150ms/80标【推断】✓，前序评分漏标已修复。
- B5 建议：互斥CLI/--stop-file/poll200ms一致✓；SO_EXCLUSIVEADDRUSE仅在§11 R5，建议提为§2/§9强制项。
- B6 必改："ns，QPC/Instant原始值"错误——QPC是ticks非ns，照实现则全部阈值/评分失效。改成统一单调时钟换算纳秒(QPC×1e9/频率、Instant→duration ns)+换算原语。建议4个u64时间戳字节序须明确；布局无越界(24B/64B)、请求响应对等无放大✓。

## C 安全与诚实
- C1 必改：VPN判定靠网卡名关键字【推断】，而"默认排除防房间成员看到"完全依赖识别正确，改名/本地化即误判泄露。改成本机实名枚举(如26.0.0.0/8+Radmin)+保守排除/UI逐卡确认+【需实测】验证。
- C1 必改：§8 GUI无VPN泄露警告，研究报告基线要求"勾选时告知房间成员可见"(Radmin二层已实测)。改成GUI+README加入明确警告。
- C1 建议：放大"对等"仅单包成立，广播扇出宜限定措辞；README声明须落地任务。
- C2 通过：§10.3/10.4/§1/§12一致限定"发现+探测≠双人对局"、不勾E2、不动Gate/62056，无越界。建议R1"已实测"加"编译通过≠功能/双机可用"限定。

## D 可实施性
- D1 必改：§3"零依赖默认"与"不再是零crate"矛盾——依赖直进[dependencies]则旧模式名存实亡。改成feature gate(默认关)收拢，普通build仍零依赖，--features才需vendor；写明lock含optional包+vendor完整。建议加lock version=3校验防stable升v4。
- D2 建议：变异测试期望值若复用被测函数即自指失效，改成手算硬编码/RFC示例；VM判据补量化门槛、自检补QPC→ns/t4′/seq回绕/乱序新判据。
- D3 通过：四分标注诚实、评分漏标已修复。建议§5过滤标【决策】、§6每路径独立socket标【推断】。

M1(B1)逐网卡bind+监听策略；M2(B2)删t4+符号表；M3(B6)时间戳统一纳秒；M4(C1)VPN实名枚举+保守排除+实测；M5(C1)GUI/README VPN警告；M6(D1)feature gate还原零依赖。
