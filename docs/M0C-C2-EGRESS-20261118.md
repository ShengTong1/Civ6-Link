## 2. 实验缺陷与纠正（必须记录，避免误读历史轮次）

### 2.1 缺陷（我造成的探针 bug，非产品缺陷）
- 第一版探针 `c2-b-send1.ps1` 用**尾字节 marker 区分三组**：baseline=0x70、radmin=**0x71**、wlan=**0x72**。
- 但 Civ6 发现 magic 是固定 4 字节 **`8D-E8-FC-70`**，agent 只对精确匹配 magic 的包计 `requests seen`。
- 结果：radmin/wlan 两组（尾字节 0x71/0x72）**被 agent 当噪声丢弃**，`seen=0` 是探针改坏了 magic，**不是"Radmin 通道不达"**。
- 曾据此一度得出"pin Radmin 收不到 / Radmin 不转发广播"的错误推论，**现予推翻**。

### 2.2 纠正
- 第二版探针 `c2-b-send1-v2.ps1`：三组统一用正确 magic `8D-E8-FC-70`，靠"每轮只发一组"隔离 → 三组全部 `seen=10`（包都到了），但仍无法区分源 IP。
- 第三版探针 `c2-b-send1-v3.ps1`：在 v2 基础上**抓取 agent 应答的源 IP**——A 的 `send_to(page, from)` 回发到"看到的广播源 IP"，其应答源 IP 与 B 广播出口接口一一对应，构成闭环判据。
- 修复两处 C# 编译错误：`ReceiveFrom` 参数须 `ref EndPoint`（非 `ref IPEndPoint`）；`LocalEndPoint` 须在首包发送后读取（未绑定时为 null）。

## 4. 结论

1. **IP_UNICAST_IF 定向跨机生效（机制层强证据，间接判据）**：应答源 IP 随 B 侧 pin 的接口切换——pin Radmin→A 的 Radmin IP 回包；pin WLAN/baseline→A 的 WLAN IP 回包。三组 `replySrc` 随 pin 严格切换，与 agent 源码 `send_to(page, from)` 行为一致，支持「`setsockopt(IPPROTO_IP, 31, htonl(ifidx))` 改变了广播出口网卡且对端可观测」。但需注意：`replySrc` 是 A 侧接收/回发网卡的 IP，非 B 侧线上抓包，反推 B 出口依赖对称路由假设（详见 §5）。
2. **字节序正确**：探针 set 用 `htonl(ifidx)`（网络序），`getsockopt` 读回主机序 7/17；产品 `PinSend`（`civlink\client\civlink_client.cpp`）用 `htonl(g_pinIfIndex)`，正确。读回函数 `ReadIfIndex` 仅存在于自测探针 `civlink\selftest\client_selftest.cpp:180-187`，**产品 DLL 无 getsockopt/ReadIfIndex**（审计 N-3，报告归属更正，非产品缺陷）。依 MSDN `IP_UNICAST_IF` 语义与设计文档 `M0C-C2-DESIGN-20261118.md:125/128/140`，host-order 会被误判为 IP 地址，故须 htonl——此为**文档支持的推断，本轮未实测 host-order 失败**，不声称任何具体错误码数值（审计 N-2）。
3. **"Radmin 不送达"结论作废**：当前 metric 调整后（A/B Radmin=200 < WLAN 优先被打破为 Radmin 靠后）、双端 Radmin 都上线的环境下，pin Radmin 组 10/10 到达并收到 22 页应答——Radmin 通道可用。
4. **广播丢包复现**：wlan 组 8/10（20%）与历史 E2-B 的 6–34% 一致，UDP 广播无 ACK 的物理特性再次印证。
5. **对 m28529「刚才那局走哪条通道」的回答**：**无法回答**——对局期间未抓包且游戏进程已重启，静态数据不足。本实验只证明**探针级发现闭环在当前环境的两条通道上均可完成**（Radmin 与 WLAN 都能送达 22 页应答）；**真实对局联机是否受通道影响未在本轮验证**，也不能据此排除游戏状态、防火墙 profile、Civ6 同 IP 去重等其它因素（审计 N-4，收紧因果外推）。

- **不得**据此宣称"真实双人对局已验证""E2-A/E2-B/E3 已通过"或勾掉任何 Gate。
- 应答源 IP 判据依赖 agent `send_to(page, from)` 回发到广播源 IP 的行为（已由 agent 源码 `main.rs:731` 确认）；`replySrc` 是 **A 侧按发往 B 广播源 IP 的路由所选的本地回发 IP**，反推「B 广播出口网卡」依赖对称路由假设，**非 B 侧线上抓包**；结论链自洽但属间接证据（审计 N-4）。
