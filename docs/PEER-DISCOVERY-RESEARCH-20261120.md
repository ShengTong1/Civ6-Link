## 0. 执行摘要

1. **发现机制**：不用 255.255.255.255 全局广播（Windows 只走首选接口，多网卡经典故障）。改为**逐网卡绑定本地 IP、发定向子网广播**（WiFi `192.168.31.255`、Radmin `26.255.255.255`），每网卡独立 socket。本地 Windows 11 实测：不开 SO_BROADCAST 时全局广播 sendto 必失败 10013，定向广播仍成功。
2. **探测协议**：以 **TWAMP Light（RFC 5357 附录 I）** 为蓝本——UDP 回显、反射端回带时间戳，RTT 免时钟同步；抖动用 **RFC 3550 A.8**（EMA 1/16）；丢包用序号间隙检测。无成熟 Rust TWAMP 库，自建最现实。
3. **最大特有风险**：Radmin/ZeroTier 是虚拟网卡，「不同网卡」可能仍走同一条物理链路，导致路径结论系统性误判。需 TTL + 出口源 IP + RTT 序列相关性判"疑似同链路"——【需实测】。
4. **Radmin 广播域已实测澄清**：Radmin 是二层 VPN，成员共享 `26.0.0.0/8` 广播域（A 机 `26.74.126.98/8`、VM `26.197.96.55/8`）。2026-11-19 VM 实验已证实广播跨成员：VM 发 100 magic → A agent `requests seen=100`，A 回 22 页源 `26.74.126.98:62900`。所以"Radmin 成员网段不同"的担心不成立。ZeroTier 广播仍【需实测】。
5. **用户已裁决（m33009/m33032 两轮 ask_user）**：
   - 功能定位：**独立新模式**（与 M0-E 发现补全并存）
   - 测速用途：**两阶段**（MVP 只展示推荐，自动切换留下一阶段）
   - 协议：**私有 UDP**（魔数+版本，不用 mDNS）
   - 广播触发：**界面按钮触发**（点「开始扫描」才广播，有明显状态与停止按钮）
   - 鉴权：**不加口令，仅魔数+版本**（完全信任环境，无强鉴权，需在 UI/README 诚实声明）
   - VPN 网卡：**默认只物理网卡**（WiFi/以太网），VPN 网卡须手动勾选才启用

## 2. 发现机制（子代理 b74c342a）

### 2.1 方案对比
| 机制 | 依赖 | 成熟度 | 适用性(10) |
|---|---|---|---|
| **UDP 定向广播逐网卡** | 标准 socket + 网卡枚举 | 极高（WinIPBroadcast/Civ6/中文案例） | **9** |
| 255.255.255.255 全局广播 | 标准 socket | 高 | 4（多网卡只走首选口） |
| mDNS/Bonjour | mdns-sd 230★ | 高 | 7（5353 冲突个案） |
| SSDP/UPnP | HTTPU | 重 | 4 |
| NetBIOS/WSD | 系统服务 | 淘汰 | 2 |

### 2.2 关键事实（审计 M5 已降级两处标注）
- **【事实+需实测】** Windows 7+ 全局广播只走 `255.255.255.255/32` 首选路由接口（WinIPBroadcast github.com/dechamps/WinIPBroadcast，309★ GPL-3.0 C，专门修 LAN+Hamachi 只看到一个网络）。**该机制在目标用户的具体网卡组合上仍需抓包实测**。
- **【事实，本地实测】** Windows 11 26100：SO_BROADCAST=0 → 全局广播 sendto 10013；定向广播（192.168.31.255/26.255.255.255）成功；optlen<4+val=1 可开广播。证据 `CivLink-M0A-audit/docs/diagnostics/a6-sobroadcast-experiments/README-A6.md`。
- **【事实，本地实测】** 项目目录带 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`，Low IL 进程 `Find-NetRoute` 返回 0x80041003，复制到 %TEMP% 成功。证据 `prototype/PHASE0-FORENSIC-RESULT.md`。→ 自检必须从无 Low 标签路径运行。
- **【推断，审计 M5 降级】** injciv6（github.com/xaxys/injciv6，~207★ exa 非 API 直核，**无 License 不可抄码**）用 MinHook 把 Civ6 RakNet 广播重定向为单播——这**是**广播→单播重定向可行的证据，但"反证游戏侧广播不可靠"是推断非事实。
- **【需实测】** 定向广播在 10.x/172.x/VPN 网卡行为；出口口实际抓包验证（勿信 Find-NetRoute）；AP 隔离可达性。

### 2.3 推荐方案（审计 M4 已明确主次）
**主路径**：每网卡独立 socket `bind(该卡本地IP:0)` + `set_broadcast(true)` + `send_to(该卡定向广播地址:port)`。
**兜底（需实测，非主路径）**：`IP_UNICAST_IF`（setsockopt FFI）仅在 bind 方案实测失效时启用。两者主次不可颠倒——bind 具体 IP 是 Windows 事实标准（socket2-ext 的 bind_to_device 就是 bind IP）。
周期 2–5s；对端单播回复；魔数+版本过滤；源 IP 须落在接收接口同子网才列入；UUID 去重、3×周期超时剔除。mDNS 仅可选兼容层，**不属 MVP**。

## 3. 多路径探测（子代理 9068d6af）

### 3.1 方案对比
| 方案 | 精度 | 开销 | Rust 可行性 | 结论 |
|---|---|---|---|---|
| ICMP ping | 中（ICMP≠UDP 行为） | 极低 | 需管理员 | 不代表游戏 UDP 路径 |
| **UDP Echo 自定义** | 高 | 极低 | **很高** | 推荐载体 |
| OWAMP RFC4656 | 极高（需时钟同步） | 中 | 无成熟库 | 过重 |
| **TWAMP Light RFC5357 附录I** | 高，**免时钟同步** | 低 | 高（自建） | **首选蓝本** |
| RTP/RTCP RFC3550 | 抖动标准定义 | 中 | 中 | 借鉴公式 |
| iperf3 | 高但自拥塞 | 高 | 外部进程 | 仅一次性对照 |

### 3.2 标准做法（可直接采用）
- **RTT 免同步**（TWAMP）：`rtt = (本地收Reply戳 − 本地发送戳) − (反射端发送戳 − 反射端收到戳)`。
- **无状态反射端原样拷回序号**（TWAMP Light 强制）。
- **抖动** RFC 3550 A.8：`D=(r_j−r_i)−(s_j−s_i)`；`J=J+(|D|−J)/16`。
- **丢包** RFC 3550 A.3/iperf3：单调序号 + 结算窗口（窗口内迟到计入，超窗才计丢失）。
- **路径标识** RFC 6812 五元组扩展为 `(ifIndex, src_ip, src_port, dst_ip, dst_port)`，每路径独立 socket+序号空间+统计窗口。
- **时间戳**用单调时钟（Instant/QueryPerformanceCounter），不用 SystemTime。

### 3.3 推断/需实测（审计 M2 已补标）
- 报文字节布局、session_token/path_id 字段、64B 定长——【推断】借鉴标准但自定义。
- 探测速率 20–50 pkt/s × 5–10s = 100–500 包/路径；丢包率只能**定性分级**【推断/需实测】（p≈1%、E=0.5% 需 1.52 万包，常驻不可行）。
- **评分公式【项目自创/需实测调参，无标准依据】**：`score=0.45·p50_norm+0.20·p95_norm+0.20·(J/10ms)+0.10·(L/1%)+0.05·stability_penalty`；归一化基准（p50_norm/p95_norm 除以什么）**未定义，实现阶段须冻结**。硬门槛：丢包>3% 或 P95>150ms 或样本不足⇒降级【推断】；迟滞：新路径优>10% 且持续 2–3 窗口才切换【推断，MVP 不实际切换】。
- **最大风险：疑似同物理链路判定【推断/需实测，阈值未冻结】**——比较各路径 observed_ttl、出口源 IP、RTT 序列相关性；高度一致则合并标注，不给独立推荐。
- 探针自扰：低速率 + ±10–20% 随机化间隔【推断】。

## 4. 安全隐私（子代理 14b8bced）

关键风险：伪造发现/冒充（高）、MITM（高）、被动泄露/指纹（中高）、反射放大（中高）、VPN 广播泄露给同房间成员（中高【推断】）、端口劫持（中）、测量准确性受本机缓冲影响（低中）。

事实锚点：RFC 8882（无机制鉴权实例名/大载荷只回已验证客户端）、CERT VU#550620 + CISA TA14-017A（mDNS 放大 2–10×）、MSDN（SO_REUSEADDR 无需特权强绑端口，服务端须 SO_EXCLUSIVEADDRUSE；SIO_RCVALL/raw socket 需管理员；XP SP2+ 不能伪造 UDP 源 IP）。

**裁决后采用的最小基线**：
- 广播由**用户按钮触发**（消解启动即暴露面）✓
- **不加口令**（用户明确选择）：只用魔数+版本，UI/README 诚实声明"无强鉴权、任何同款助手都能列出彼此、仅限信任环境"
- **默认只物理网卡**，VPN 须手动勾选 + UI 告知"VPN 房间其他成员可能看到发现包" ✓
- 定长≤512B、响应≤请求、周期≥1s、最小字段（无 MAC/主机名/全部网卡）、SO_EXCLUSIVEADDRUSE、临时端口、不改防火墙/不提权

未来增强（不进 MVP）：Ed25519+E2EE、PAKE/SRP、设备审批 ACL、UPnP（初版禁止）。

## 5. M1 硬冲突：零依赖约束（审计最关键发现）

审计核实：`civlink/agent/Cargo.toml` L9-11 明确零依赖 + `cargo +1.75.0 build --offline`（无 crate 缓存）。报告 v1.0 推荐的 socket2 0.6.5（依赖 libc ^0.2.172 + windows-sys ≥0.60,<0.62）、if-addrs 0.15.0 **直接破坏该硬约束**，且 v1.0 完全未提及。

**裁决结果（m33073，v1.2）**：**新功能用库 + 旧 FFI 保留 + cargo vendor 固化**。
- 用户先质疑零依赖约束（m33049「为什么有这个不合理约束？用现成 rust 库，手写的不完善就删掉，以官方开源案例为主」）。
- 子代理 3c7a351d 实证核实（`docs/RUST-NETLIB-FACTCHECK-20261120.md`）：socket2 0.6.5（rust-lang 官方、881★、15 亿+下载、MSRV 1.70）**在 Windows 官方不支持 recvmsg、无通用 setsockopt**，egress 四件事 ①②③ 覆盖不了、④ 不等价；微软针对 IP_PKTINFO 的官方案例 rmmc.cpp 本身就是手写 WSAIoctl+WSARecvMsg，与项目实现同构。→ "以库删掉手写 FFI"在本功能点不成立。
- 但新功能的大部分可用库：**if-addrs 0.15.0**（网卡枚举，底层 GetAdaptersAddresses）+ **socket2 0.6.5**（set_broadcast + bind 具体 IP）。旧 egress FFI 保留。
- `cargo --offline` 无缓存：引入 crate 后必然失败，除非 `cargo vendor` 固化依赖 + `.cargo/config.toml` source replacement；vendor 后 `--offline` 仍可构建（vendor 即本地源）。代价=仓库增大（windows-sys 约 33 万行绑定）、可审计面外移——用户已知悉并接受。

端口规划更正（审计建议）：34718 是 agent IPC/本地数据面端口，**不是**纯 IPC；新功能建议预留 63010（发现）/63011（探测），与现有 62900-62999/62056/34718/47584 均不冲突。
