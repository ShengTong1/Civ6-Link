## 1. 已确认的设计优点

提交件把 F2 定义为本机构建、真实客户端加模拟 Peer 的非发布原型；明确不改真实游戏包、不动网卡/防火墙/metric，并把 H1/H2/H8 与 R1 留给 M0-B。这与 F1 的限定裁定方向一致。

它也正确保留了 F1 的两个关键观察：刷新会创建新 socket，首帧 `0.0.0.0:0` 不能作为已知 Peer 端点。S2 仅观测、不过滤/吞掉/改写游戏调用，是本次批准的前提。

## 2. S1–S4 开工前必须写入设计/实现约束

### 2.1 不用广播路由推导 62056 监听地址

草案 §3.2（第 54 行）沿用 `Find-NetRoute 255.255.255.255` 选择 `<出口IP>`，并失败时静默回退 `127.0.0.1`。F2 的本机 62056 测试地址并不等同于广播出口；项目此前也观察到接口/metric/路由随重启改变。自动回退会让 Agent 看似成功启动，却可能监听错误地址并产生假阴性/假阳性。

改为显式 `--bind-ip`（只接受当前主机本地地址），启动日志同时记录该地址及其接口别名；未指定或绑定失败时 fail-closed 并停止数据面模拟。若需要纯回环自检，使用显式 `--loopback-selftest`，不能把它当成真机数据面结果。

### 2.2 避免把 H2/R1 偷带进 S1/S5

提交件 §1.2（第 24 行）说 H2 与 R1 留给 M0-B，但草案 §3.2（第 54 行）、§5（第 105–107 行）又让模拟 Agent 在同机绑定 `:62056` 并应答真实游戏加入请求。规范 v2.1 §4.2 把游戏通配 `0.0.0.0:62056` 与 Agent 特定地址 `Fake-IP:62056` 共存明确列为 H2/R1；只要执行这个 bind 或投递，就已经触碰该门槛。

F2 观测版不得让 Agent bind `:62056`，不得设置 `SO_REUSEADDR`，也不得用其 bind/投递结果推断 H2。Agent 通过现有 CVLH2 接收 Hook 观察到的真实出向请求，再用独立临时 UDP socket 做受限回包。该回包只探测客户端是否出现接收/API 行为，不代表真实 Peer 的源端口或协议行为。若无法在不绑定 `:62056` 的条件下实现该实验，应停止在观测，不得以“模拟需要”为由扩展到 H2。

### 2.3 FakeEndpoint 键必须包含代次和隧道会话

草案 §3.4（第 76–80 行）列出的键只有 `(socket_id, FakeEndpoint)`，而类型 `PeerEndpoint` 缺少规范 §4.3 的 `tunnel_session_id`；测试清单提到 `socket_generation`，但它不在实际键里。这会导致逻辑 socket id 复用后旧映射可能命中新 socket，或不同隧道会话的 Peer 被混为一项。

实现键至少应包含 `(session_id, logical_socket_id, socket_generation, FakeEndpoint)`；远端值至少包含 `(peer_id, tunnel_session_id, peer_endpoint)`。正向和反向查询都需定义唯一性、冲突行为、过期/关闭时的双向删除及池耗尽行为。此 crate 是数据结构原型，不得声称已实现可用于 DLL 的生命周期联动。

### 2.4 `WSARecvFrom` 必须遵守同步/重叠 I/O 边界

规范 §2.1 与 §4.2 要求保持非阻塞和异步语义。`WSARecvFrom` 可能返回 `SOCKET_ERROR/WSA_IO_PENDING`，此时不能读取 `WSABUF`、来源地址或完成字节数；真正完成可能经 overlapped、事件或 IOCP 后到达。本阶段不批准增加完成通知 Hook。

Hook 可以记录调用参数类别、句柄、目标端口、返回值及立即读取的错误码；仅当同步成功且 `bytesReceived` 有效时才能读缓冲区摘要。对 pending/失败路径只记状态，不碰缓冲区。detour 必须调用原函数并保持调用参数、返回值、`WSAGetLastError`/`WSASetLastError` 可观察语义；`bind` 同理。观测路径不得做阻塞 IPC、文件 I/O 或等待。

### 2.5 Q5 计数定义必须与当前 UDP 通道一致

草案 §3.5（第 85–87 行）将 Agent 不在描述为 `WSAECONNREFUSED`，并提出 UDP `sendto` would-block/backlog 高水位。对未连接 UDP socket，向本机无监听者的 `sendto` 常不能可靠地同步报告“Agent 不在”；异步 ICMP 错误也不能等同于某一帧投递失败。当前 Hook IPC 是同步本机 UDP，不存在可直接读取的队列长度。

S1–S4 应只报告可直接计数的事实：Hook 观察到的原始调用数、CVLH2 尝试/成功/失败/错误码、Agent 实收 CVLH2 帧数、数据面 Agent socket 实收数、测试负载发送数。它们是不同层次的计数，只有明确相同的报文集合才可相等对账。把“Agent 进程存活”作为独立健康探测；没有健康握手时不得把 sendto 成功宣称为 Agent 已收到。不要称 UDP send buffer 为应用队列，也不要把“没有同步错误”写成零丢包。

## 3. D1–D5 详细裁定

### D1 — 批准

H1-A/B/C、H2、H8、R1 以及 Design I/II/III 选择继续留在原阶段门槛。S1–S5 的观测只能记录本机本构建行为，不能把它们改写成相关假设已关闭。

### D2 — 有条件批准 S1–S4

可以开始 Agent 模式、纯观测 Hook、独立 FakeEndpoint crate 和机械自检；先将 §2.1–§2.5 的约束落实到设计/接口和自检，再进 Hook 真机注入。S1 模式不得因 bind 失败继续伪装为运行成功；S2 的异步接收路径不得解引用未完成的缓冲区；S3 映射必须有代次/会话隔离；S4 分开统计不同层的数据量。

### D3 — 有条件批准一次 S5 点击

允许一次手动点击“加入”来观察本构建客户端行为，前提是 S1–S4 机械自检通过、游戏进程退出后才重链 DLL、Agent 不 bind `:62056`、没有远端/第二台机器目标。响应只使用 D4 限定替代方案。遇到崩溃、卡死、系统错误或加载异常立即停止本轮并保留证据；不重试、不修游戏、不伪造成功。该动作不代表真实加入或联机。

### D4 — 不批准当前按 `src:port` 每端点应答；批准一次性本机替代

当前“每个新 `src:port` 回一次”的全局上限不明确；刷新 socket 会不断创建新端点，可能扩成多次响应。改为每次运行**总计最多 1 个 20 B 固定响应**，仅当源 IP 经确认是本机地址且源端口非零时发送；源为 `0.0.0.0:0`、非本机、端点不完整或无法确认本机时只记录不回。使用临时源端口，不 bind `:62056`；响应载荷固定、无重试、不得带真实玩家/网络信息。报告必须写“本机单次任意数据报探测”，不能称为游戏协议应答、Relay RTT 或真实房主模拟。

### D5 — 限定批准

允许纯内存测试使用 `127.0.127.1..=127.0.127.100` 作为候选地址池，测试分配/冲突/回收。F7 是上游实现路径的实证，不等于 CivLink 本机已验证，也不构成最终选段。不得给回环接口加地址、改路由、对该段执行真实 bind/发送，亦不得删除 `198.18.0.0/15` 作为后续 H1 对照。

## 4. 必须采用的结论边界

即使所有 S1–S5 通过，最多可称：

> 在本构建和本机模拟条件下，观察到 Civ6 的相关 Winsock 调用及本机单次测试数据报行为；FakeEndpoint 内存映射单测通过。实验未验证远端 Peer、真实协议兼容、H2/R1 绑定投递、双机加入或游戏开局。

“调用顺序 bind→先 WSARecvFrom→再 WSASendTo”只能从同一 socket、同一进程、结构化单调序号/QPC 时间记录中判定；只凭分散计数器不能证明顺序。非阻塞属性也必须用 `ioctlsocket(FIONBIO)`/`WSAEventSelect` 等可见证据或明确标“未观察”，不能从 `WSARecvFrom` 调用本身推断。

## 5. 执行顺序与停点

1. DSH 先按 §2 更新设计草案并给 S1–S4 的实现边界定稿；这属于设计更正，不需要另等一次项目范围裁定。
2. 实现并运行 S1–S4 的离线/机械自检；每一步报告源文件差异、命令、退出码、原始输出和哈希。
3. 任何 Hook DLL 重链前，按 F1 裁定关闭 Civ6 并确认进程退出；不得在仍映射旧 DLL 的进程里覆盖文件。
4. S4 通过后，按 D3/D4 受限条件进行一次 S5。若无法避免 bind `:62056`，停在 S4 并提交问题，不执行该真机步骤。
