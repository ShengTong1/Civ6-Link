## 1. 目标

在真实 Civ6 双机（A 房主 / B 加入者，同一 WLAN）下完成：

1. **B 稳定看到 A 的房间**（消除原生发现 1/100 窗口 + 广播丢包 6~34% + 70s socket 生命周期）；
2. **B 加入 A 的房间**（数据面 62056 双向通信建立）；
3. 全程由 civlink 代理链承载，**B/A 的 Civ6 无需任何修改**。

## 2. 架构（设计规范 v2.1 §4.5 Discovery Adapter / §4.6 Game Data Adapter 落地）

```
A 机（房主侧）                        B 机（客户端侧）
Civ6 ──civlink_hook.dll──> agent-A ──┐  ┌── agent-B <──civlink_hook.dll── Civ6
   (62056 帧捕获/注入)                │  │   (62056 帧捕获/注入)
                     [agent-A ↔ agent-B 数据通道（UDP 直连，决策2=路线A）]

发现链路（决策1=路线A）：
B 刷新 magic(100 包) → A 机 agent-A 绑全 100 端口收到任意 1 包
  → agent-A 用真实广告页（B1-p1-e2e run-102852 捕获的 22 页）应答 B
  → B 看到真实房名（dingzihan2022 的游戏）→ B 点加入
```

## 5. 边界（诚实声明，贯穿全程）

- 本程序交付**双人真实联机链路**（发现+加入+数据面），但**对局完整性/长稳/跨网/加密**不在本轮验证范围（Noise E2EE 属设计规范 §8，后续轮次）。
- 工具级/模拟证据（步骤 6/7）不得宣传为双人真实联机验证；双人结论以 E2-A/E2-B/E3 真实双机证据为准。
- Agent 永不 bind 0.0.0.0:62056、永不 SO_REUSEADDR；数据面转发每帧单次、不重传不篡改。

## 7. v1.1 补充（2026-11-17，代码勘察结论——重大简化）

- **Discovery Adapter 代码已存在**：LanSimState::new（main.rs:544-563）已处理 bind 失败——
  某发现端口被占用时 ind_fail+=1 并跳过该端口继续；62900 失败时 reply_sock 回退到第一个
  成功绑定的 socket（567-576）。因此 A 机 Civ6 占用 62900 时，agent 自动绑 62901-62999
  （99 端口），**无需任何 agent 代码改动**。
- **主循环已支持全部所需组合**：--sim-lan-listen 0.0.0.0（F5 全端口监听）+
  --sim-real-capture（B1 真实广告页捕获）+ --simulate fixture（应答页集）三者可并存
  （run() L1562-1587/1665-1669/1794-1807/617-628），即 M0-B Discovery Adapter 的
  **完整运行形态已由现有 CLI 参数组合提供**。
- **数据面可能无需 agent 转发**：广告页无 IP 字段（real-page-01.bin 实测，仅房名+mod 列表），
  B 点加入后向「应答源 IP:62056」发 join（S5 观测 dst 端口固定 62056）。真实双机中应答源=
  agent 绑定的 A 机 WLAN IP:62901-62999 → B 向 A 机 WLAN IP:62056 直连 → 落到 A 机
  Civ6 的 62056 socket（游戏建房时已 bind）。**Game Data Adapter（agent 转发）设为备选**：
  E2-B 双机实测先验证数据面直连，仅当直连失败才实现 agent↔agent 62056 转发。
- **步骤重排（v1.1）**：3=写 A 机启动脚本（组合参数封装，非新代码）；4=本机模拟闭环自检
  （游戏占 62900 场景：agent 绑 99 端口 + trigger 双路应答）；5=写 M0B 双机操作单；
  6=子代理审计；7=双机真实验证 E2-A/E2-B/E3（先测数据面直连）；8=Gate A 复核+结案登记。

  除非直连失败。

  A 机 Civ6 62056，行为一致。登记时如实说明。
