## 1. 这条实验想回答什么

F2 的 S5 真机实验（`docs\F2-S5-JOIN-REAL-CLIENT-20261114.md`）观察到文明6 客户端在点「加入」后，
会向 `127.0.0.1:62056` 发一个 8 字节出向帧，并在无人应答时按 **0.5×2ⁿ 秒**退避重试：
`+0.500 / +1.001 / +2.001 / +3.999 / +8.001 / +15.999 / +32.001 / +63.999 / +128.001 s`。

设计 v0.3 §5.2 因此规定：在**对端全程不回包**的前提下，这 10 帧必须都通过转发链路到达对端
Agent，且 `seq` 连续、无重复、无重排、**不做应用层重传**（RFC 8085，P0-3 铁律）。

F3-C 就是用这份**真实观察到的**序列驱动回环原型，验证转发链路是否破坏上述语义。它**不**发明
新序列，也不改变间隔。

## 2. 自检设计（`civlink\run-f3c-backoff-selftest.ps1`）

1. 前置：`127.0.0.1:34718`（Agent 控制通道）与 `127.0.0.1:21347`（对端 Agent 转发接收端口）
   都必须空闲，否则退出码 2。
2. 启动一个 Agent：
   `--forward-to 127.0.0.1:21347 --forward-listen 21347 --simulate-datapath --bind-ip 127.0.0.1
   --loopback-selftest --listen-seconds 301 --stop-file <out>\stop --quiet`
3. **运行期**实测 `Get-NetUDPEndpoint -LocalPort 62056`，断言 Agent 没有占用游戏数据端口
   （H2 门槛的运行时侧面；代码级护栏在 F3-A 的 `--port` 与 F3-B 的 `--listen`）。
4. 以 S5 的 10 个间隔发 10 个 CVLH2 帧：`seq=1..10`、`dst=127.0.0.1:62056`、`flags=0x21`
   （OBSERVED|VIA_WSASENDTO）、载荷 8 字节 `17 32 00 00 FF FF` + 每帧不同的 2 字节
   （`4FAC/51A1/558A/5D5A/6CFA/8C3A/CABA/47BA/41BA/35BA`，逐字节抄自 S5 frame-log）。
5. **对端全程不回包**——这是 §5.2 的策略边界，也是与 F2 D4「≤1 次 20B 本地探针」的分界：
   D4 探针由 Agent 的 datapath 侧发往 62056 场景的**发送方**，与这里的转发目标无关。
6. 主序列发完后追加 **3 帧故意错误的负向对照**（见 §2.1）。
7. 写 stop 文件，等 Agent 干净退出（退出码 0），再读 summary 与三份日志做断言。

`-TimeScale` 可缩短窗口（默认 1.0，即真实间隔）。本轮采信证据是 `1.0`，也就是**真的等了
255.5 秒**，Agent 窗口 301 秒、实际运行 258.4 秒。验证脚本改动时用 `0.15`（38.3 s 压缩窗口，
`-160401`，结果同全时序一致）。

**R2 修复说明（v3）**：
- R2-M1：脚本 Grab 锚从 `\(accepted non-discovery` 改为 `\(accepted frames that reached the
  forward stage`（对齐 F3-A 第四轮新标签），否则 `$seen` 恒空、断言必红。
- R2-M2：断言 13 从「只比端口」升级为**解析 `forward sock` 与 `first sender` 的完整
  `IP:PORT` 并逐项匹配**（回环通配 `0.0.0.0` 以 `127.0.0.1` 呈现视为相等），并断言端口 ≠ 62056。
- R2-L4：间隔容差从 `400×scale + 250`（650 ms，对 0.5 s 首间隔无分辨力）收紧为 `250×scale`。

### 2.1 负向对照（v2 新增，审计 F3C-R-05 / F3C-R-06）

v1 只能产出「0 重复、0 缺口」，而这恰恰也是**坏掉的或从未被触达的计数器**会打印的东西。
三帧故意错误的输入把「没看到问题」变成「能看到这个问题」：

| 帧 | 内容 | 期望 |
|---|---|---|
| F11 | `seq=10` 再发一次（与主序列第 10 帧重复） | `duplicates == 1` |
| F12 | `seq=12`（跳过 11） | `seq gaps == 1`、`missing_frames == 1` |
| F13 | 与 `seq=1` **同一 4-tuple**（同 session / 同逻辑 socket / 同 generation / 同 dst），载荷不同 | `mappings created` **仍为 1** |

F13 的载荷**故意**与 `seq=1` 不同：若复用它，两条 peer-recv 行会共用同一个 sha256，破坏主序列
「每个载荷唯一匹配」的断言。F13 测的是键的构成（4-tuple 而非帧序号），不是载荷。

三帧走独立 socket、间隔 120 ms、在 stop 之后单独记账（`$schedLines = $fwdLines | First 10`），
所以主序列的 seq 1..10 顺序断言、载荷 sha256 断言、退避间隔断言都不受重复的 `seq=10` 干扰。

## 6. 结果：证明什么、不证明什么

**证明（本机回环，限本原型实现）**

- 游戏实测的 10 帧退避序列**逐帧**穿过 Agent 转发链路，`seq` 连续、无重复、无重排。
- 转发是**一帧一次**：`forwarded == peer received == 13`，代码路径只有一次 `send_to`，
  没有应用层重传或补发。
- 8 字节载荷在三个位置（发送侧原始字节、forward-log、对端接收侧日志）的 **sha256 完全一致**。
- 13 帧（含 3 帧故意错误的输入）复用**同一个映射键**（`mappings created == 1`），
  说明键由 4-tuple 构成，不受帧序号或载荷影响。
- **负向对照能被看见**：重复、缺口、少帧各自被精确计数（1/1/1），所以主序列上的 `0` 有意义。
- **D4 硬约束成立**：整轮只有 1 次 20B 探针，其余 12 帧以 `already_sent` 拒绝。
- Agent 全程未占用 62056。

**不证明**

- 不证明真实双机、跨网、NAT、Relay 转发的行为：这里没有 Relay，也没有第二台机器。
- 不证明游戏侧行为：帧由测试脚本构造，不是游戏进程发出的；**CVLH2 封装是 42 B 帧头 + 8 B
  载荷 = 50 B**，不是 v1 文档误写的「618 字节」；Hook 只在 M0-A 观察工具里验证过，未参与本轮。
- 不证明退避序列的**来源语义**：只证明「按这个序列发送时链路不破坏它」，不证明游戏为何选
  0.5×2ⁿ，也未观察到放弃点（S5 记录到第 10 帧 128 s 后仍在重试）。
- 不证明时延与 0.5 s 首窗预算的关系：回环 RTT 远小于该预算，且本轮对端不回包，没有往返。
- 不证明长稳：单次运行 258.4 秒。
- 不证明并发：单会话、单逻辑 socket、单映射键。
- 不证明「不重传」由断言 20 独立证明（见 §3 说明，机制证据在代码路径）。
